<objective>
**As a** lifter who has run the same lift for a year, **I want to** widen the chart beyond the last three
months, **so that** I can see a long arc rather than only recent noise.

This plan completes ANLY-06. 09-01 shipped the performance screen with its three metrics over the last
ninety days; this plan adds the range switch and the two longer ranges, gives the screen its primary entry
point on the exercise detail screen, and extends the executed durability spec to cover both.

Deliberately NOT in this plan: anything on the Home or History tabs (09-04 and 09-05, running beside this
one in the same wave), the Records screen (09-03), and any further downsampling. A decade of weekly buckets
is roughly five hundred points, which an SVG path renders without difficulty and which the chart's own
marker cap already handles; adding a downsampler would be complexity this design has deliberately designed
away.

Purpose: finish the exercise-performance surface and make it reachable from the obvious place.
Output: three ranges, three metrics, one entry link, and green browser evidence for all of it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| an unbounded all-time read -> the render path | Removing the date bound removes the only thing limiting how many rows reach the chart on a long-lived account. |
| a range selection -> the reader's date predicate | A user-chosen value crosses into a query bound; an off-by-one or a wrong unit silently returns the wrong window. |
| bucketed values -> the rendered headline | A bucket's chosen representative becomes a number a lifter reads as a performance they achieved. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-9-29 | Denial of Service | the unbounded all-time range on years of history | medium | mitigate | The read stays two batched queries regardless of row count, the aggregation is linear, and the chart's existing marker rule keeps a long series to one path plus one marker. The UI-SPEC's own guard notes roughly five hundred weekly buckets for a decade, which an SVG path renders without difficulty; no downsampler is added and none is needed. |
| T-9-30 | Repudiation | a bucketed value the lifter never achieved | high | mitigate | Each bucket keeps the best value in it, never the mean, and a dedicated unit assertion plus a browser assertion both pin it. Averaging a best-metric would print a number that never happened. |
| T-9-31 | Tampering | a wrong range bound | medium | mitigate | The range-to-days map lives in the package's constants module and a grep gate forbids a day-count literal in either the screen or the reader; the all-time case emits no predicate at all rather than a large sentinel number. |
| T-9-32 | Repudiation | an estimated-1RM omission caption counting sessions outside the visible range | medium | mitigate | The dropped count is computed within the selected range, so the caption never names sessions the lifter cannot reach by widening it. |
| T-9-33 | Information Disclosure | an unbounded read on a local database that outlived a user switch | medium | accept | The read reuses the shipped signed-in-only guard verbatim; the `user_id` column is stamped server-side on push and is not a usable local filter. The all-time range widens the date window but not the account scope. |
| T-9-SC | Tampering | npm/pnpm installs | high | accept | Zero new external packages in this plan; `react-native-svg` was installed and pinned by 09-01 against Expo SDK 57's own version map. No registry install runs here. |
