<objective>
**As a** lifter who just finished a set of an exercise I have been running for months, **I want to** see
what I have actually done on it over time, **so that** I know whether I am progressing or spinning.

This plan is the phase's **tracer**: one exercise, one range, from stored `logged_set` rows through a pure
aggregation package, through a real SVG chart, onto a real route, proven in a real browser. It is
production-quality, not a prototype — every piece it lands is the piece the finished phase ships.

It is deliberately the first thing built because it is the only place in the phase where the architecture
could be wrong: this repo has no chart primitive, `react-native-svg` is not yet a declared dependency, and
09-RESEARCH §1 flags one unverified assumption — that `react-native-svg` under `react-native-web` maps
`accessibilityRole="image"` + `accessibilityLabel` onto a queryable `role="img"` with an accessible name.
If that does not hold, the selector strategy for every later chart spec in this phase changes, and this
plan must be the one that finds out.

Deliberately NOT in this plan, each being a later plan's whole subject rather than a gap here:
the `1y` / `all` ranges and the range switch (09-06), the weekly bucketing every other surface needs
(09-02), the Records screen (09-03), the two tab cards (09-04, 09-05), and the two shipped-code
corrections in `WorkoutSummary.tsx` (09-03). The screen this plan ships renders the `3m` range only, with
no range switch — a functionality gap that 09-06 fills without changing any call site's shape, never an
architectural one.

Purpose: prove the whole vertical — pure maths, local read, SVG renderer, route, browser evidence — before
any of it is built out horizontally.
Output: a working, tested, browser-proven exercise performance screen covering ANLY-06's metric half and
ANLY-10 in full.

    - Given an inverted output range, a HIGHER value produces a SMALLER y coordinate. This is asserted explicitly, because an axis flip renders a mirrored chart that still looks plausible.
    - `paddedDomain([100, 105])` pads by ten percent of the span on each side and never starts at zero; `paddedDomain([100, 100])` still returns a non-zero-width domain so a genuinely flat series draws at the vertical centre rather than vanishing.
    - `buildChartGeometry` on two or more values returns a line path starting with a move command followed by line commands, an area path that closes down to the baseline, and one marker per value, all coordinates rounded to two decimals.
    - `buildChartGeometry` on a single value returns exactly one marker and empty line and area paths — a one-point polyline is invisible and a line to an implied origin would assert a workout that never happened.
    - `exerciseSeries` with metric `heaviest` returns one point per session holding that session's top completed record-eligible set weight; a warm-up-only session and a partial-only session both produce NO point at all rather than a zero.
