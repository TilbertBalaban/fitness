<objective>
**As a** lifter who trains on no fixed weekday, **I want to** have my week measured as the last seven
days rather than resetting my visible progress at midnight on an arbitrary day, **so that** a Sunday-evening
session never looks like a failed week.

This plan writes the three pure aggregations the phase's two remaining tab cards need: rolling-window and
trailing-bucket boundaries, the history trend series with its delta, and the weekly achieved-versus-target
computation. It ships no screen and no read; it is a deliberate foundation plan.

card) and 09-05 (the History trend card) run in the same wave and would otherwise each add a module to
`packages/analytics-engine` and each append a line to its barrel — two parallel worktrees editing the same
file at the same position, which is precisely the seam that produced this repo's Phase 4 wave-2 merge
conflict. Landing all remaining package work in one earlier wave makes the package a read-only dependency
for every plan that follows, and no plan after this one touches `packages/analytics-engine` at all.
Reversible: the modules could be moved back into their consumers with no behaviour change.

Deliberately NOT in this plan: any React component, any database read, any screen wiring. Those are 09-04
and 09-05, which consume this plan's exports and own their own surfaces end to end.

Purpose: remove the phase's last cross-plan file seam while pinning the two time rules — D-07's rolling
window and D-09's absent-is-not-zero — in one testable place.
