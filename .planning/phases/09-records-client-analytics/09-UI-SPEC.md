## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not applicable. Unchanged from Phases 1/3/4/5/6/7: this is React Native + React Native Web, and shadcn's Radix primitives cannot run inside a native `View`/`Text` tree. `components.json` correctly does not exist. |
| Component library | Hand-rolled RN components under `apps/mobile/components/`, extending the shipped set. This phase adds exactly five: `TrendChart`, `SegmentedChipRow`, `RecordRow`, `WeeklyProgressCard`, `HistoryTrendCard`. Every one styles itself against the same NativeWind token set already in `apps/mobile/tailwind.config.js`; none introduces a second visual language. |
| Icon library | `@expo/vector-icons` (`Ionicons`), unchanged. The Phase 1 D-06 rule still holds: an icon's colour is resolved by `useThemeColors()` and passed as the `color` prop, never a NativeWind `className` on the icon. This phase's new glyphs (`chevron-forward`, `arrow-up`, `arrow-down`, `checkmark`) follow that mechanism. |
| Font | System default, unchanged — no `fontFamily` override exists or is introduced. |
| Charting | **`react-native-svg` only** (D-05/D-06). It is the single new runtime dependency this phase may add. It ships one build that renders on native *and* on `react-native-web`, so there is **no `TrendChart.web.tsx` sibling** — one file, one renderer, one appearance, and the chart is therefore exercisable by the Playwright durability harness. No Skia, no `victory-native`, no `recharts`, no second charting framework. |

**Design decisions this document resolves that CONTEXT.md left open.** Each is a discretion item bounded by an existing D-decision, decided here rather than left to the executor:

1. **[CLAUDE'S CALL] Where the four surfaces live** — Home gains a card, History gains a card *and* a link, and two new routes are added. No tab is added or restructured (CONTEXT: "the tab structure already exists and should not be restructured"). See **Navigation & Placement**. *Reversibility: reversible — placement is a route move, not a data change.*
2. **[CLAUDE'S CALL] `react-native-svg` draws shape only; every number is a React Native `<Text>` outside the `<Svg>`** (R16). This is the entire mechanism by which charts stay legible at maximum OS font scale — `SvgText` does not honour `Text` scaling on either target. *Reversibility: one-way in spirit — reintroducing in-SVG text silently breaks the accessibility guarantee every prior phase was verified against.*
3. **[CLAUDE'S CALL] A progress bar is two nested `View`s, not SVG.** SVG is reserved for the one shape a `View` genuinely cannot draw (a polyline). Using it for a rectangle would widen the dependency's blast radius for nothing. *Reversibility: reversible.*
4. **[CLAUDE'S CALL] The weekly card is titled "Last 7 Days", not "This Week."** D-07 forbids copy implying Mon–Sun; "This Week" implies exactly that. ANLY-08's requirement wording is satisfied by the content, not by reusing its phrasing. *Reversibility: reversible — a copy change.*
5. **[CLAUDE'S CALL] `most_reps_at_weight` is a records-only metric with no time series.** Plotting it needs a *chosen weight* to hold constant, which is a drill-down this phase does not ship. It stays fully available on the Records screen (all four PR metrics per ANLY-03) and is simply absent from the performance chart's metric switch. *Reversibility: reversible — additive.*
6. **[CLAUDE'S CALL] Weekly targets are one full pass through the active program's current cycle** (D-08's "derived from the active program", made concrete). A program's day list is its weekly template; summing across it is the only reading that needs no new authoring surface. *Reversibility: reversible — a manual override is additive, exactly as D-08 says.*
7. **[CLAUDE'S CALL] Two corrections to shipped Phase 5 code** — the repeated "New PR" badge, and the bare `e1RM: —` cell. Both are pre-existing defects this phase's requirements (ANLY-02, ANLY-10) make load-bearing. See **Correction Notes**.
8. **[CLAUDE'S CALL] A declining trend is drawn in `foreground-muted`, never `destructive`** (R19). A down week is information, not an error, and the second semantic colour stays reserved for destructive actions. *Reversibility: reversible.*

## Spacing Scale

Declared values (already shipped in `apps/mobile/tailwind.config.js`, multiples of 4 — inherited unchanged, no new token):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding |
| sm | 8px | Compact element spacing, progress-track height |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Screen horizontal padding, section gaps |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions inherited, still binding:**

- **48×48px minimum hit target** on every interactive element. This phase's hit targets: each metric chip, each range chip, each `RecordRow`, the History "Records" link, and the "View performance" link on the exercise detail screen. Nothing shrinks below the floor at any OS font scale.

**New exceptions this phase introduces:**

| Constant | Value | Rationale |
|---|---|---|
| `TREND_CHART_HEIGHT` | `120` | The SVG canvas is a fixed-height drawing surface, not spacing. It carries **no text** (R16), so it has nothing to scale and deliberately does **not** grow with OS font scale — the text around it does. 120 is on the 4px grid. |
| `MIN_CHART_WIDTH` | `200` | Floor for `resolveChartWidth()`. Below this a polyline is noise; a container narrower than this renders the surface's empty/partial state instead of a squeezed chart. |
| `PROGRESS_TRACK_HEIGHT` | `8` (= `sm`) | Progress-bar track and fill. On the scale; also does not scale with font size — the numeral beside it does. |
| `MAX_POINT_MARKERS` | `12` | Above this point count the per-point circles are omitted (they merge into noise); the final point always keeps its marker. |

`resolveChartWidth(windowWidth)` mirrors the exported `resolveHeroImageWidth` idiom already shipped in `components/ExerciseImageTile.tsx` and consumed via `useWindowDimensions()` in `app/exercises/[id].tsx` — same pattern, exported from `TrendChart.tsx`, unit-testable without a renderer:

```
resolveChartWidth(windowWidth) = max(MIN_CHART_WIDTH, windowWidth − 2×lg (screen padding) − 2×md (card padding))
                               = max(200, windowWidth − 80)
```

## Typography

Declared values (already shipped — this phase adds no fifth size and no third weight):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 20px (1.43) |
| Body | 16px | 400 — 600 accepted for headings-within-cards and CTA text | 24px (1.5) |
| Heading | 20px | 600 | 24px (1.2) |
| Display | 28px | 600 | 34px (1.21) |

**Phase-specific role mapping:**

- Screen titles ("Records"; the exercise name on the Performance screen) → **Heading**.
- Card headings ("Last 7 Days", "Trends") → **Body, semibold** — matching `WorkoutSummary`'s shipped "Muscles Trained" / "Per-Exercise Breakdown" convention, not Heading, so a card inside a scroll never competes with a screen title.
- **The one headline figure per trend surface** (current-window value on `HistoryTrendCard`; latest value on the Performance screen) → **Display**. This is this phase's deliberate first use of the `display` token, and it is the focal point of both trend surfaces: "what have I achieved" is answered by one large number before any chart shape is read.
- Record row exercise name → **Body, regular**. Its value/date line → **Label, `text-foreground-muted`**.
- Progress-track label ("Sets") → **Label, `text-foreground-muted`**; its numeral (`14 / 18`) → **Body, semibold, `text-foreground`**.
- Chart axis labels (first/last date beneath the chart), value-range caption, delta chip, and the "not plotted" caption → **Label, `text-foreground-muted`**.
- Metric and range chip labels → **Label** (matching `FilterChipRow`'s shipped chip).
- PR badge text → **Label, semibold, `text-accent`** (unchanged from the shipped `WorkoutSummary` badge).
- Empty/error state headings → **Heading**; their body copy → **Body, regular, `text-foreground-muted`** (the exact shipped pattern).

## Color

Declared values (already shipped in `apps/mobile/global.css`, inherited unchanged — **no new hex is introduced this phase**):

| Role | Value (light) | Value (dark) | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `#FFFFFF` | `#09090B` | Screen background (`bg-background`) |
| Secondary (30%) | `#F4F4F5` | `#18181B` | Cards, rows, chip fills, skeletons (`bg-surface`) — every surface this phase adds sits on this |
| Accent (10%) | `#2563EB` | `#3B82F6` | See extended reserved-for list below |
| Destructive | `#DC2626` | `#EF4444` | Destructive actions only — **this phase ships no destructive action and therefore uses this colour nowhere** |
| Foreground | `#09090B` | `#FAFAFA` | Body/heading text, headline figures, progress numerals |
| Foreground (muted) | `#71717A` | `#A1A1AA` | Labels, captions, axis labels, chart baseline, progress track, declining-trend glyph |

**Accent reserved for** (Phase 1's list, extended additively by Phases 3/4 — never widened to "all interactive elements"). New this phase:

- **The trend line stroke, its area fill (at `fillOpacity 0.12`), and the "now" marker** in `TrendChart`. The chart's data is the accent's whole job on that surface — a line drawn in `foreground` would read as chrome.
- **The filled portion of a weekly progress track.** The track itself is `foreground-muted` at 20% opacity (matching the shipped `border-foreground-muted/20` divider in `WorkoutSummary`).
- **An improving-trend delta glyph and its percentage** (`arrow-up`).
- The selected metric/range chip's border + checkmark — **not new**; inherited verbatim from `FilterChipRow`'s shipped selection rule.
- The PR badge pill (`bg-accent/10` fill, `text-accent` label) — **not new**; unchanged from Phase 5.
- Text links: "Records" (History header), "View performance" (exercise detail) — **not new**; the shipped text-link rule.

**Not accent, explicitly:**

- **A declining trend** renders its glyph (`arrow-down`) and percentage in `foreground-muted` (R19). It is neither an achievement (accent) nor an error (destructive).
- **A progress track at or over target** stays accent-filled and gains a muted `checkmark` glyph; it does not change hue. There is no free hex for "done", and inventing one would break the 60/30/10 split.

**The `ThemeColors` interface needs no new field.** It ships exactly `{ accent, foregroundMuted, surface }`, and `TrendChart` needs precisely those three — because R16 removes all text from the SVG, no `foreground` colour is ever required inside a chart. Do not extend `lib/theme-colors.ts` this phase; a new field there must be mirrored by hand into `global.css` and is a known drift hazard the file's own comment warns about.

## Phase-Wide Rules

Extends R1–R15 (all still binding: R1 wrap-and-grow, R2 ~3s web cold start, R3 explicit-submit-may-block, R4 new surfaces never truncate, R6 no spinner for local reads, R13 the working-set predicate, R15 shipped surfaces stay pixel-identical). This phase adds:

- **R16 — `react-native-svg` draws shape only. No text ever renders inside an `<Svg>`.** Every number, date and label associated with a chart is a React Native `<Text>` rendered as a *sibling* of the `<Svg>`, so it honours OS font scale, the app's colour tokens, and the screen reader. `SvgText` does not appear anywhere in this codebase. This is the concrete mechanism behind "charts degrade legibly at large font scale."
- **R17 — A chart is never drawn for absent data (D-09).** Zero points renders the host surface's empty state; **one** point renders a labelled dot with no line (a one-point polyline is invisible and a line to an implied origin asserts a workout that never happened). No metric is ever plotted at zero to represent "no data" — a real logged zero and an absent measurement must never look alike.
- **R18 — Every analytics set count goes through the same predicate the exercise strip already uses** — `parentSetId === null && countsTowardWorkingVolume(setType) && completed`, i.e. `countCompletedWorkingSets`'s exact rule (`components/ExerciseStrip.tsx`), extending R13 from the logging read paths to the analytics read paths. Two visible definitions of "a set" in one app is a correctness bug, not a cosmetic one (CONTEXT § Specific Ideas). PR-eligibility keeps its own, separately-correct predicate `countsTowardRecords` (`packages/pr-rules`) — the two are deliberately different and must not be merged.
- **R19 — A declining trend is never drawn in `destructive`.** See **Color**.
- **R20 — Every chart is announced once, as a sentence.** The `<Svg>` root carries `accessible`, `accessibilityRole="image"` and an `accessibilityLabel` built by the exported `trendChartSummary()`; every child element inside it is hidden from assistive tech (`accessibilityElementsHidden` / `importantForAccessibility="no-hide-descendants"`) so a reader announces the series once rather than reciting anonymous paths and circles.
- **R21 — Every window length, bucket size and range is a named exported constant** (CONTEXT § Specific Ideas). No numeric literal for a time span appears at a call site.

## `TrendChart` — the phase's highest-value contract

One file, `components/TrendChart.tsx`. No `.web.tsx` sibling: `react-native-svg` renders on both targets from the same source (D-05/D-06), which is precisely why these screens get real browser evidence in the Playwright durability harness rather than only unit tests.

### Props

```ts
export interface TrendPoint {
  key: string;          // stable react key (bucket start ISO date or session id)
  value: number;        // already in display units — the chart performs no conversion
  valueLabel: string;   // pre-formatted, e.g. "102.5 kg" (formatWeight output)
  dateLabel: string;    // pre-formatted, e.g. "12 Aug"
}

export interface TrendChartProps {
  points: TrendPoint[];      // chronological, oldest first
  colors: ThemeColors;       // { accent, foregroundMuted, surface } — no new field needed
  width: number;             // from resolveChartWidth(useWindowDimensions().width)
  metricLabel: string;       // e.g. "Heaviest weight"
  rangeLabel: string;        // e.g. "Last 3 months"
}
```

The component is **hook-free and computation-free** — it receives already-bucketed, already-formatted points, matching `RecommendationBanner`'s and `PlateStripView`'s shipped no-computation contract, and making it directly invocable by a test with no renderer (the `SetRowView` / `CycleStripView` / `WorkoutSummaryView` house pattern). All aggregation lives in the pure package (D-04/D-10).

### Anatomy (top to bottom, all inside the host card, `bg-surface rounded-md p-md`)

1. **Value-range caption** — RN `<Text>`, Label/muted: `"{minLabel} – {maxLabel}"`. Omitted entirely when `points.length === 1`.
2. **The `<Svg>`**, `width={width}` `height={TREND_CHART_HEIGHT}`:
   - **Baseline** — a `<Line>` across the bottom edge, `stroke={colors.foregroundMuted}`, `strokeOpacity={0.3}`, `strokeWidth={1}`. This is chrome marking the chart's floor; it is **not** a zero line and no data is ever drawn on it.
   - **Area** — a `<Path>` from the polyline closed down to the baseline, `fill={colors.accent}`, `fillOpacity={0.12}`, no stroke. No gradient (a gradient needs `Defs`/`LinearGradient` and adds nothing legible at 120px).
   - **Line** — a `<Path>`, `stroke={colors.accent}`, `strokeWidth={2}`, `fill="none"`, `strokeLinecap="round"`, `strokeLinejoin="round"`.
   - **Markers** — `<Circle r={3} fill={colors.accent}>` per point, rendered **only when `points.length <= MAX_POINT_MARKERS`**. The final point always renders at `r={4}` regardless of count — that is "where you are now."
   - **Y-scaling** — the vertical domain is `[min(values), max(values)]` with a 10% pad top and bottom, **not** `[0, max]`. A weight series that never approaches zero must not be flattened against the bottom of the frame. When every value is identical (`min === max`), the series renders as a flat line at the vertical centre with its single value shown in the caption — a genuinely flat series is true and is drawn as such; this is not the D-09 fabricated-zero case.
3. **Axis label row** — an RN `<View className="flex-row flex-wrap justify-between">` holding two `<Text>` (Label/muted): the first point's `dateLabel` and the last point's `dateLabel`. Only two labels, ever — a dense axis is unreadable at 120px and unreadable again at 200% font scale. `flex-wrap` so at maximum font scale the two labels stack instead of colliding (R1/R4).

### Single-point rendering (R17)

`points.length === 1` renders **no line and no area**. The `<Svg>` draws one `<Circle r={5}>` at the horizontal centre, vertical centre. Beneath it, a single RN `<Text>` (Body/foreground): `"{valueLabel} · {dateLabel}"`. The value-range caption is omitted. This is the "one workout logged" state and it must read as a fact, not as a broken chart.

### Zero-point rendering (R17/D-09)

`points.length === 0` returns `null`. **The component never renders an empty frame.** Every host surface is responsible for its own empty state and must not call `TrendChart` with an empty array — the `null` return is a backstop against a host that forgets, not a design.

### Accessibility (R20)

- The `<Svg>` carries `accessible`, `accessibilityRole="image"`, `accessibilityLabel={trendChartSummary(props)}`.
- Every `<Path>`, `<Line>` and `<Circle>` inside carries `accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"`.
- The axis label row and the caption are ordinary `<Text>` and are announced normally after the chart — they are real text, not decoration.

`trendChartSummary` is exported and unit-tested independently of any renderer:

| Case | Announced sentence |
|---|---|
| Many points | `"{metricLabel} over {rangeLabel}. {n} points. From {first.valueLabel} on {first.dateLabel} to {last.valueLabel} on {last.dateLabel}. Lowest {minLabel}, highest {maxLabel}."` |
| One point | `"{metricLabel} over {rangeLabel}. One point: {p.valueLabel} on {p.dateLabel}."` |
| Zero points | never reached — the component returns `null` before this |

### Maximum-font-scale behaviour

The chart canvas is 120px tall at every font scale — it holds no text, so it has nothing to scale (R16). Everything around it (headline, caption, axis labels, chips, the "not plotted" caption) is ordinary RN `<Text>` and grows normally; the host card grows vertically to fit and never clips. The axis row wraps. Nothing horizontal shrinks: `resolveChartWidth` is derived from window width alone and is independent of font scale.

## S1 — Last 7 Days Card (ANLY-08, D-07, D-08, D-09)

`components/WeeklyProgressCard.tsx`, rendered on the Home tab immediately below `NextUpCard`, inside the existing `gap-lg` column. Card shell: `gap-md rounded-md bg-surface p-md`, matching `NextUpCard` exactly.

**Read-only. It is not a press target and navigates nowhere** — muscle-group drill-down is ANLY-05, explicitly Phase 10, and a card that looks tappable but is not is worse than one that plainly is not.

**Heading:** `"Last 7 Days"` (Body, semibold). **Never "This Week"** — D-07 forbids copy implying a Mon–Sun reset. Directly beneath, a Label/muted subheading: `"Rolling window ending today."` — this makes the window's semantics visible rather than implied.

**Window:** `PROGRESS_WINDOW_DAYS = 7`, a rolling window ending today, computed from a date supplied as an argument (D-10) — never a clock read inside the pure layer.

**Three tracks, in this fixed order:**

| Track | Label | Achieved (rolling 7 days) | Target (D-08) |
|---|---|---|---|
| 1 | `Sets` | count of completed working sets, using **exactly** `countCompletedWorkingSets`'s predicate (R18) | sum of `targetSets` over every exercise in every day of the active program's current cycle |
| 2 | `Exercises` | distinct exercise ids with ≥ 1 completed working set | count of distinct exercises across those same days |
| 3 | `Muscles trained` | distinct **primary** muscle groups of those exercises | count of distinct primary muscle groups across those same days |

Target derivation is **[CLAUDE'S CALL] #6**: one full pass through the current cycle's day list is treated as a week's prescribed work. Where the active program does not express a target — no active program, a cycle with zero days, or a day whose exercises carry `targetSets: null` — the track shows the achieved figure with **no denominator and no bar** (D-08's "show the achieved figure without a denominator rather than inventing one"), plus a Label/muted caption on that track: `"No target set."`

**Track anatomy** (each track is a `gap-xs` block, and every track holds a 48px minimum block height so the three read as an evenly-weighted set):

```
Sets                                  14 / 18
[███████████████░░░░░░░░░░░░░░░░]
```

- Label row: `flex-row flex-wrap items-center justify-between` — label (Label/muted) leading, numeral (Body/semibold/foreground) trailing. `flex-wrap` so at maximum font scale the numeral drops to its own line rather than either side truncating (R1/R4). **No `numberOfLines` anywhere in this card.**
- Track: `View`, `height: PROGRESS_TRACK_HEIGHT` (8px), `rounded-full`, `bg-foreground-muted/20`.
- Fill: nested `View`, same height, `rounded-full`, `bg-accent`, width `${clamp(achieved / target, 0, 1) * 100}%`.
- **Over target:** the fill clamps at 100%; the numeral still reads truthfully (`22 / 18`) and gains a trailing muted `checkmark` glyph (Ionicons, 16px, `colors.foregroundMuted`). No hue change (see **Color**).
- **Accessibility:** each track's container carries `accessibilityRole="progressbar"`, `accessibilityValue={{ min: 0, max: target, now: achieved }}`, and `accessibilityLabel={"{label}: {achieved} of {target}"}` — or, with no target, `accessibilityRole="text"` and `accessibilityLabel={"{label}: {achieved}, no target set"}`. A bare coloured rectangle is otherwise silent.

**States:**

| State | Rendering |
|---|---|
| **Empty** (no completed working set in the window) | The **whole card** renders the empty state — heading, then Heading-role `"Nothing logged in the last 7 days"` and Body/muted `"Log a workout and your progress appears here."` **No tracks, no zero bars, no zeroed numerals** (D-09). ## ANLY-10 — The Estimated-1RM Contract (D-02)

`estimated1RM` returns `null` above `E1RM_MAX_VALID_REPS = 10`. D-02's requirement is a **presentation** discipline at every call site: never a computed number, never a bare blank that reads as a bug. This phase pins one vocabulary for it.

**One exported copy constant, built from the rule itself so the two can never drift:**

```ts
export const E1RM_ABOVE_CAP_COPY = `Not meaningful above ${E1RM_MAX_VALID_REPS} reps`;
```

**One typed three-branch result at every e1RM display site** — a discriminated union, matching the shipped `ProgressionResult` / `RecommendationBanner` house idiom, so a new branch added later is a compile error rather than a silently blank cell:

```ts
type E1rmDisplay =
  | { kind: 'value'; display: string }   // a valid estimate exists
  | { kind: 'above-cap' }                // completed weighted sets exist, ALL above the rep cap
  | { kind: 'unavailable' };             // no completed weighted sets at all, or the estimator threw
```

The `above-cap` / `unavailable` distinction is load-bearing: `unavailable` must **not** claim the rep cap as its reason when the real reason is "nothing was logged", because a wrong explanation is worse than none.

**Rendering per surface:**

| Surface | `value` | `above-cap` | `unavailable` |
|---|---|---|---|
| Workout summary e1RM cell (existing) | `"e1RM: {display}"` | `"e1RM: {E1RM_ABOVE_CAP_COPY}"`, Label/muted | `"e1RM: —"` (the shipped `formatWeight(null)` em dash, unchanged) |
| Records screen, `best_e1rm` empty state | n/a | body copy `"Estimated 1RM is only shown for sets of {E1RM_MAX_VALID_REPS} reps or fewer."` | same copy — a records list cannot distinguish the two, and this copy is true either way |
| Performance screen, `e1rm` metric, **no** qualifying session | n/a | Heading `"No estimated 1RM to show"` + Body/muted `"Every logged set for this exercise was above {E1RM_MAX_VALID_REPS} reps. Estimated 1RM is only meaningful at {E1RM_MAX_VALID_REPS} reps or fewer."` Both switches stay visible so the user can pick another metric. | falls through to the screen's ordinary "No history for this exercise" empty state |
| Performance screen, `e1rm` metric, **some** qualifying sessions | chart renders qualifying points **only** — non-qualifying sessions are omitted, never plotted at zero (D-09) — plus a Label/muted caption directly beneath the axis row: **`"{n} sessions above {E1RM_MAX_VALID_REPS} reps aren't plotted — estimated 1RM isn't meaningful there."`** (`"1 session"` singular via the shipped `pluralize` idiom.) | n/a | n/a |

That caption is the concrete answer to "never a blank that looks like a bug": a chart with visible gaps must say why, in place, in the user's own terms.

## `SegmentedChipRow` (new shared component)

`components/SegmentedChipRow.tsx`. A **single-select** chip strip, used three times this phase (Records metrics, Performance metrics, Performance ranges, History trend metrics). It exists so those four call sites cannot drift apart.

- Chip anatomy is copied verbatim from the shipped `FilterChipRow`: `flex-row items-center gap-xs rounded-md border bg-surface px-md py-sm`, `style={{ minWidth: 48, minHeight: 48 }}`, `border-accent` when selected / `border-foreground-muted` otherwise, an accent `checkmark` Ionicons (16px, `useThemeColors().accent`) when selected, label `text-label font-normal` in `text-accent` / `text-foreground-muted`.
- **Difference from `FilterChipRow`:** single-select (`selectedId: string` + `onSelect`, not `selectedIds: string[]` + `onToggle`), `accessibilityRole="radio"` with `accessibilityState={{ selected }}`, and the container carries `accessibilityRole="radiogroup"` with an `accessibilityLabel` naming the dimension ("Record metric", "Performance metric", "Time range", "Trend metric"). A silent group of chips is otherwise unannounceable.
- **No title line.** `FilterChipRow` renders a title above its chips; this component does not — its dimension is named by its `accessibilityLabel` and by the surface it sits on, and a visible title on four different surfaces would add four redundant lines.
- **Overflow:** horizontally scrolling (`ScrollView horizontal`, `showsHorizontalScrollIndicator={false}`, `contentContainerStyle={{ alignItems: 'center', gap: 8, paddingVertical: 4 }}` — `CycleStrip`'s shipped values). Chips **never wrap** to a second row: a switch that changes height on selection would shift everything below it on every tap.
- **Long text:** a long label widens its chip (R4 — grow, never truncate); it never wraps inside the chip and never truncates. `FilterChipRow`'s `numberOfLines={2}` is deliberately **not** inherited — that exists for a dense filter list, not a four-item switch.
- **Empty:** `options.length === 0` returns `null`, matching `FilterChipRow`/`CycleStripView`. In practice unreachable — every call site passes a fixed constant array.
- **Hook-free view + thin wrapper**, matching `CycleStripView`/`SessionHistoryRowView`: `SegmentedChipRowView` takes `colors` as a prop and is directly invocable by a test with no renderer.

## Correction Notes — shipped Phase 5 code

Two defects in shipped code that this phase's requirements make load-bearing. Both are narrow, both are recorded here so the plan treats them as corrections rather than fresh design. **R15 still holds for everything else in `WorkoutSummary.tsx` — no other pixel changes.**

The `PR` suffix is retained so the badge stays recognisable as the same affordance the durability suite already asserts on; `e2e/workout-summary.spec.ts`'s expectations must be updated in the same plan, not left to drift.
