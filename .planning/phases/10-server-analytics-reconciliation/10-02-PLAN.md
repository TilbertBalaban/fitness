## Flagged planner assumptions

- **Probe item ANLY-09 / `unclassified` — surfaced, not silently resolved.** The deterministic edge
  probe returned an `unclassified` row for ANLY-09 that no automatic rule could classify. Read
  concretely, it is: *what happens when an edit deletes the last set of a session, or moves a session
  to a different `local_date` — is the vacated rollup cell invalidated, or merely left stale?* This
  plan answers it with delete-then-recompute over the union of the old and new dates, and asserts the
  answer in both the unit and the e2e layer. The probe row itself stays `unresolved` in the coverage
  record; this paragraph is its required surfacing.
- **[ASSUMED] Full per-exercise replay, not date-scoped replay** (10-RESEARCH Assumption A1). The
  replay reads all of the touched exercise's completed history rather than only the sessions after
  the earliest touched date. Date-scoped replay is cheaper for a lifter with years on one lift but
  must also handle a session moving *earlier* than another session that already read it as "prior" —
  meaningfully harder to get right, and not justified before 10-04 measures the real cost. If 10-04's
  budget assertion fails against the seeded corpus, date-scoping is the named follow-up.
- **[ASSUMED] Chronological order for the replay** is `workout_session.local_date`, then
  `logged_set.logged_at`, then `logged_set.set_index`. `local_date` leads because it is the field a
  lifter edits when backfilling history, and `logged_at` on a backfilled session reflects when it was
  typed in, not when it was lifted.

## Grep-gate hygiene

Every **negative** grep in this plan's acceptance criteria (a count that must be 0) is evaluated over
**comment-stripped** source. Strip first, then count — for TypeScript and TSX use
