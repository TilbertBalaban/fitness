<objective>
**As a** lifter who does not want to author a program by hand, **I want to** answer a short set of
questions and receive a complete, pre-periodized routine, **so that** I can start training tomorrow
without designing a mesocycle myself.

This plan is the phase's **tracer**: one set of wizard answers (hypertrophy / intermediate /
3 days / 60 minutes / full body / no emphasis / no deload) travels through a brand-new shared pure
package, out as a plain data tree, onto a preview screen, and — only after an explicit confirm —
into real `routine`/`routine_cycle`/`routine_day`/`routine_exercise`/`routine_exercise_cycle_target`
rows that the existing builder can open and the existing progression engine can move.

It is deliberately first because this is the only place in the phase where the architecture could be
wrong. No package in this workspace has ever emitted a whole aggregate tree as plain data; no writer
has ever materialized a program from a structure that already fully describes it; and `canEquip` has
never been importable outside `apps/mobile`. If a pure package cannot produce a tree the existing
write path accepts unchanged, every later plan in this phase changes shape — and this plan must be
the one that finds out.

Deliberately NOT in this plan, each being a later plan's whole subject rather than a gap here:
the `excluded_exercise` synced table and its server registration (11-02), its device mirror and
exclusion UI (11-03), the split templates beyond full body (11-04), the full multi-step wizard with
every control and the reroll affordance (11-05), and the GEN-07 parity proof plus the real-browser
durability run (11-06). `split-templates.ts` in this plan carries the complete table SHAPE and
resolution contract with `full_body` entries populated; 11-04 adds rows to that same table without
changing its signature. That is a functionality gap, never an architectural one.

Purpose: prove the whole vertical — closed vocabularies, promoted equipment predicate, pure
generator, plain tree, bulk writer, preview-then-confirm — before any of it is built out.
Output: a generated program that is, from the moment it exists, an ordinary program.
</objective>

## Worktree bootstrap (run before anything else)

This plan runs in a fresh worktree. Run `corepack enable`, then `pnpm install`, then
`npx turbo run build --filter="./packages/*"`. Without the build step every `@fitness/*` import
fails resolution and reads as a code error that is not one. This plan makes that failure mode worse
than usual: it creates a NEW workspace package that two apps then import, so after adding
`@fitness/program-generator` to `apps/mobile/package.json` and `apps/api/package.json` you must run
`pnpm install` again and then rebuild `./packages/*` before either app's typecheck or Jest run can
resolve it.

## Grep-gate hygiene

**comment-stripped** source. Strip first, then count — for TypeScript and TSX use
`grep -vE "^\s*(//|\*|/\*)" <file> | grep -c "<token>"`. Positive greps (a count that must be at
least N) are evaluated over the raw file.

gate forbids in code. An unstripped count would make the explanation self-invalidating.
