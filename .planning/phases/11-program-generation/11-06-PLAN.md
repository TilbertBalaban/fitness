<objective>
**As a** lifter who accepted a generated program, **I want to** edit it, reorder it and add to it
exactly as if I had written it myself, and have it progress by the same rules, **so that** accepting
the app's suggestion costs me nothing later.

This plan is GEN-07's proof. It is deliberately last because it can only be written once the whole
generator exists: a parity fixture table that both a hand-built and a generated prescription travel
through, run by three separate Jest processes; and a real-browser durability scenario that
generates, saves, closes and reopens a real `@powersync/web` database, reads the tree back through
the shipped builder loader, edits it through an ordinary builder mutation, and confirms the edit
survives.

The trap this plan exists to avoid is named explicitly in the research: a "parity" test that diffs
the two trees' shapes proves nothing, because it never runs the progression engine. Both programs'
resolved prescriptions must go through the real `recommendNextPrescription` and produce deeply equal
`ProgressionResult`s.

Purpose: turn GEN-07 from a structural claim into an executed one.
Output: three processes running one fixture table, and a green Playwright run against a real
database.
</objective>
