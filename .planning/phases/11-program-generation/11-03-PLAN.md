<objective>
**As a** lifter who will not train a movement my shoulder cannot tolerate, **I want to** mark it
excluded once and see every exclusion I have made in one place, **so that** no generated program
ever prescribes it and I can change my mind later.

This plan brings the exclusion list onto the device and wires it into generation. 11-02 made
`excluded_exercise` a real, per-user, synced Postgres table; 11-01 built and unit-tested the hard
exclusion filter inside `buildCandidatePool`. This plan closes the loop: the SQLite mirror so
PowerSync has somewhere to land the rows, one read/write module, the two screens a user touches,
and the single call that feeds real ids into `generateProgram`.

Deliberately NOT in this plan: the split templates beyond full body (11-04), the full multi-step
wizard (11-05), and the parity and durability proofs (11-06).

Purpose: make GEN-03 true at runtime rather than only in a unit test.
Output: an exclusion a user makes on the exercise screen is an exclusion the generator honours.
</objective>
