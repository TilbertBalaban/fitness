<objective>
**As a** lifter alternating bench press and rows, **I want to** finish a set of bench, get moved straight
to rows with no rest countdown, and only then see the timer start once rows are done, **so that** the app
matches how a superset is actually performed instead of resting me in the middle of one.

Purpose: everything a superset needs now exists except the behaviour. `workout.tsx`'s
`handleCheckmarkPress` has zero group awareness — it writes `rest_target_at` on every completion. D-13
turns that into one condition at the rest-start call site, and D-14 adds a second, narrower advance that
must be evaluated BEFORE `shouldAutoAdvance` and must never be folded into it (Pitfall 5): D-14 fires on
every completed set of a non-final member regardless of that exercise's own target-set completion, while
`shouldAutoAdvance` fires only once the whole prescription is met. Conflating them would make a superset's
first exercise never advance, defeating D-14 entirely.

Output: SETS-07 and SETS-08 observable end to end, plus the two purely visual affordances D-12 asks for.
</objective>
