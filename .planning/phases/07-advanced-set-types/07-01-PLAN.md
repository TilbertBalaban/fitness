<objective>
**As a** lifter mid-workout, **I want to** turn a set I just finished into a drop set by tapping its
set number, **so that** the extra weight-drop work I actually did is recorded under the set it belongs
to instead of being lost or logged as a separate set.

This is the phase tracer. It wires ONE path — set-number tap, sheet, Drop Set, a `drop`-typed child
written with `parent_set_id`, read back through the query, ordered beneath its parent, rendered
indented with a `D` badge — through every layer Phase 7 will touch, and proves the architecture
before any expansion plan builds on it.

Purpose: 07-RESEARCH.md's two load-bearing findings are both on this path. (1) Three read-path type
shapes stop short of carrying `parentSetId`/`side`, and `loadSessionTree`'s SELECT does not name
either column, so a badge built first would render correctly in a unit test and do nothing in the
app (Pitfall 1). (2) `orderForDisplay` buckets warm-up-vs-not and has no concept of a child, so a
child added to an earlier set after a later set already exists renders at the END of the list
(Pitfall 2). Both are closed here, on the thinnest possible slice.

Output: a working drop-set group, the two published counting predicates every later plan reads, and
the Wave 0 ordering/picker test suites that did not exist before.
</objective>
