<objective>
**As a** lifter who only realises a set was a failure set once it is over, **I want to** tap its set
number and pick Failure, **so that** the set is recorded as what it actually was without me re-entering
anything.

Purpose: 07-01 wired one row of the picker (Drop Set) to prove the path. This plan completes the
behavior table. Six of the seven rows retype the tapped row and two insert a sub-entry beneath an
unchanged parent — an inconsistency that is a genuine data-model subtlety, not a copy-paste variant
(Pitfall 6). A naive "pick a value, set `set_type` to it" handler would write `set_type = 'drop'` onto a
parent row, which D-07 and the badge map both say must never happen. This plan also lands D-09's
destructive confirm — the only place in this phase where logged data is deleted — and flips
`docs/session-vocabularies.md`'s reserved rows to written.

Output: SETS-01 and SETS-04 complete, and the group-mutation seam (`set-groups.ts`) 07-05 and 07-08 both
build on.
</objective>
