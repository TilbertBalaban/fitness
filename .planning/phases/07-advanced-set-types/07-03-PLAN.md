<objective>
**As a** lifter doing a drop set on the third of four prescribed sets, **I want to** see 3/4 rather than
6/4 and stay on the exercise I am still working, **so that** the app's own count of my workout matches
what I actually did.

Purpose: `shouldAutoAdvance` counts rows where `setType` is the working type, and
`countCompletedWorkingSets` counts rows that are not warm-ups. Neither has ever seen a child row,
because until 07-01 no code path could create one. The moment children exist, both inflate — the strip
reads 4/4 after two real sets and the pager advances mid-drop-set. This is the same class of failure
WINDOWS #136 already fixed once for a different cause. D-19 names `auto-advance.ts`;
07-RESEARCH found `ExerciseStrip.tsx` as a fifth location CONTEXT.md's own decision text does not
enumerate, and it is in scope here explicitly rather than by assumption.

Output: D-10's counting rule holds at both call sites, and the last inline copy of the warm-up
exclusion is gone.
</objective>
