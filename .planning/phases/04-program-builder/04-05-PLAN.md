<objective>
**As a** lifter comparing my Push day against my Pull day, **I want to** swipe between days and drag
an exercise into place with a handle that is always visible, **so that** shaping a week is one gesture
rather than a trip through a menu.

Purpose: this is the phase's largest unbudgeted technical risk, flagged in CONTEXT.md and unresolved
past MEDIUM-LOW confidence by the research. `apps/mobile/package.json` contains no
`react-native-gesture-handler`, no `react-native-reanimated`, no pager library and no reorder
library, and both D-21 and D-23 need dependencies that must behave identically on React Native and
React Native Web. `PITFALLS.md` §5 is precisely this failure mode, and this machine has no Xcode and
no Android SDK — the web target is the only place the interaction can actually be exercised.

The research's recommendation, carried here: use `react-native-tab-view` for paging (it ships its own
native/web split internally — `react-native-pager-view` on native, `PanResponder` on web) and build
the drag handle **directly** on gesture-handler plus reanimated rather than on a pre-built reorder
library, because both of those have first-party web-support documentation and none of the surveyed
reorder libraries claims web support at all.

Output: a swipeable day deck, an always-visible drag handle with a non-gesture equivalent, and a
written record of exactly where native and web diverge.
</objective>
