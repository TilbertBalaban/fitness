<objective>
Give the Programs screen the same optional `userId` / `db` injection seam the workout and gym screens
already have, and teach the durability harness to seed a routine tree and mount that screen — so
04-16 can drive the day-lifecycle controls in a real browser against a real database.

Purpose: `04-VERIFICATION.md` records that "every UI surface in this phase is verified by unit tests +
typecheck + a successful web export only. That is a real limitation of the evidence, not a
formality." This gap-closure run exists because tested library functions were never reachable from a
screen — the one class of defect a pure-helper test cannot see. `.claude/CLAUDE.md` grants standing
authorization for Playwright here and states plainly that a green run against a real `@powersync/web`
database is real evidence, and to prefer executing a spec over asserting it would pass. This plan
builds the seam that makes that possible.

Output: `ProgramsScreenProps`, a `seedRoutineTree` test-support helper with raw readers, and an
`openProgramsScreen` harness method.
</objective>
