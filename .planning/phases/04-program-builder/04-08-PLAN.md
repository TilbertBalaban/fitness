<objective>
**As a** lifter planning a mesocycle, **I want to** see my block as a row of cycles above my days,
drop a deload where I want it, schedule time off, and change only the numbers that differ in a given
week, **so that** the shape of the block is legible at a glance and one heavier week is one small
edit.

Purpose: 04-06 gave cycles a table and 04-07 gave per-cycle targets a sparse override table and one
shared resolver. Neither is reachable from the app yet. This plan is where D-22's pinned cycle strip,
D-12's visually distinct deload and time-off entries, and D-10's per-field override resolution become
something the user can actually do.

Output: a builder whose cycle strip changes which numbers the days show, and per-cycle targets you
can set and reset.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cycle selection (view state) -> write path selection | One piece of UI state decides whether an edit writes the base prescription or a cycle override; getting it backwards silently rewrites the wrong row |
| user keystrokes -> `routine_exercise_cycle_target.target_*` | Free text becomes integer columns on a second table with the same value rules as the base |
| local override rows -> the unique (exercise, cycle) pair the server enforces | A client that inserts rather than updates produces an op the server rejects for the whole aggregate |
