<objective>
**As a** lifter walking up to a bench with no signal, **I want to** see what the app thinks I should lift
for this exercise, **so that** I do not have to remember last session or guess.

This plan is the phase's **tracer**: one exercise, one recommendation, from stored rows to rendered text,
production-quality end to end. It fills `packages/progression-engine` (D-01) — a reserved slot that today
exports only a placeholder and has no jest config and no test script — with the minimum path that proves
the architecture: raw logged rows in, a gym-achievable weight and rep target out, rendered on the workout
screen. Every later plan in this phase expands outward from this proven slice rather than adding a new
layer beneath it.

Deliberately NOT in this plan, and each is a later plan's whole subject rather than a gap here: the
per-side/failure-set normalisation (08-03), the shortfall streak and RIR tolerance band (08-04), the D-07
preference branch (08-05), and the client/server parity fixture (08-06). The `offeredReduction` field on
the recommendation branch is declared here and always `null` — a functionality gap, not an architectural
one, so 08-04 populates it without changing any call site's shape.

Purpose: prove the whole vertical before building any of it out horizontally.
Output: a working, tested, wired progression engine covering PRGR-01, PRGR-02, PRGR-05, PRGR-06, PRGR-07.
