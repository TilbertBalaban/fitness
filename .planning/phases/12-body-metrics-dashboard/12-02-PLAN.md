<objective>
Give the user a place to see and log their body measurements: the `/body-metrics` overview, the
metric entry sheet with its own keypad, the track-a-kind picker, and the length-unit half of the
display conversion boundary.

Purpose: 12-01 proved a bodyweight can reach Postgres, but only from a test. This plan is the first
surface a real person can touch. It also settles the D-08 display question for circumference kinds —
one preference (`user_preference.weight_unit`) drives both mass and length display, so a user can
never see kilograms alongside inches.

Output: a working overview screen, an entry sheet that commits in one confirm, and `cm`/`in`
conversion at the single existing units boundary.

**Shared-seam note.** `packages/api-contracts/src/units.ts` is owned by this plan alone in this
phase. `apps/mobile/lib/db/body-metrics.ts` was created in 12-01 (wave 1) and is extended here;
12-03 extends it again in wave 3. No same-wave plan touches either file.

**MVP note (planner flag):** the ROADMAP `**Goal:**` line for Phase 12 is not in user-story form, so
no story is framed here. See 12-01's `<planner_assumptions>`.
</objective>
