<objective>
Give the user their trend: a per-kind detail screen with the shipped chart, the app's existing window
vocabulary, and the ability to correct or remove any entry.

Purpose: BODY-03 is the payoff for BODY-01/BODY-02. Phase 9 already settled the chart contract, the
no-text-inside-SVG rule and the one-sentence accessibility announcement; a body-metric trend is the
same shape with a different series source, so this plan adds a query and a screen and no charting
code at all (D-11). It is also the first real-browser proof that a metric written through 12-02's
sheet survives, dedupes and renders.

Output: `loadBodyMetricTrend`, the `/body-metric-trend` route, the entries list with its edit/delete
action sheet, and a Playwright spec driving all of it against a real `@powersync/web` database.

**Shared-seam ownership.** This plan is the wave-3 owner of the three append-only shared seams:
`apps/mobile/app/__durability.web.tsx`, `apps/mobile/lib/db/test-support.ts` and
`apps/mobile/playwright.config.ts`'s `durability` `testMatch` array. **Append only — never rewrite,
never reorder, never remove an existing entry.** `apps/mobile/lib/db/body-metrics.ts` and
`apps/mobile/components/MetricEntrySheet.tsx` were last touched by 12-02 in wave 2; no wave-3 plan
other than this one touches either.
