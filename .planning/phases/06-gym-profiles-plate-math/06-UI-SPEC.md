# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn is not applicable. Unchanged from Phase 1/3/4/5: React Native + React Native Web, shadcn/Radix cannot run inside a native `View`/`Text` tree. `components.json` correctly does not exist. |
| Component library | Hand-rolled RN components under `apps/mobile/components/`, extending the exact set Phases 1–5 shipped. This phase **reuses verbatim**: `PrimaryButton`, `TextField`, `SelectField`, `DetailSection`, `ArchiveDialog` (extended, see below), `ErrorBanner`, `NavBackButton`, `RoutineActionSheet`-shaped action sheets, `SwapSuggestionList`, `SessionActionSheet`, the Session `Menu` popover, `NumericKeypad`'s reserved band. This phase **adds**: `GymProfileEditor` (bars/plates/dumbbells/machines form), `PlateStrip` (the equipment/plate band that fills `NumericKeypad`'s reserved slot), `EquipmentAvailabilitySheet`, `SwitchGymSheet`. No new component introduces a second visual language — every one styles itself against the same NativeWind token set. |
| Icon library | `@expo/vector-icons` (`Ionicons`), unchanged. Per Phase 1 D-06: an icon is used only where its color does not need to dynamically track theme state through a prop the icon library owns — in that case `useThemeColors()`/the local `GLYPH_COLORS` pattern (`SessionActionSheet.tsx`) resolves the color and is passed as the `color` prop, never a NativeWind className on the icon itself. |
| Font | System default, unchanged — no `fontFamily` override exists or is introduced this phase. |

**Design decisions this document resolves that CONTEXT.md/RESEARCH.md left open** (Claude's Discretion items and RESEARCH.md's Open Questions #1/#2, decided here per the established design system, not re-litigated with the user):

1. **"Bar types and weights" (GYM-02) resolves to one bar per profile, described by a preset + weight, not a repeatable bar list.** The schema carries a single nullable `barbellWeightKg` column (D-01, verified) — no bar-label column exists and none is invented. "Type" is a UI-only preset selector (Standard / Women's / EZ Curl / Custom) that writes a value into that one field; it is not a second persisted concept. See **Gym Profile Editor**.
2. **Where GYM-07's "mark unavailable" action lives (RESEARCH Open Question #2):** `SessionActionSheet` gains a fifth row, **Equipment**, appended after Info (additive-only, per this codebase's established never-reorder convention) — never a new visible action-bar button, keeping the already-dense per-exercise action bar (Phase 5 D-13) unchanged. See **Session Action Sheet — Equipment row**.
3. **Where GYM-04's "switch gyms mid-program" lives:** the session `Menu` popover (Phase 5 Amendment A.2) gains a fourth row, **Switch Gym**, between Session Note and Discard — Discard stays last and destructive-colored. Starting a workout itself gains no new step: a session is stamped with whatever gym is currently active (`user_preference.default_equipment_profile_id`, D-02) with zero added friction to the start flow, matching D-19's low-friction bias. See **Session Menu — Switch Gym row**.
4. **The equipment/plate band's exact content per `equipment_type`:** barbell + ez_bar → plate breakdown; dumbbell → nearest pair; machine + cable → stack range/increment/base resistance; kettlebell, bodyweight, band, medicine_ball, exercise_ball, foam_roller, other, and no-profile-resolved → band collapses to 0 height (no inventory model exists or is needed for these in this phase). See **Equipment / Plate Band**.
5. **The band grows past its 40px reservation only when it must hold a real tap target** (the not-loadable state's two correction values, or an "Add plates" recovery link) — an explicit, documented exception to Phase 5 D-20's "exactly 40px" reservation, justified because Phase 5 named this phase as the band's owner and R4's own wrap-and-grow philosophy already governs every other surface in this app; a passive/informational band stays at exactly 40px. See **Equipment / Plate Band**.
6. **Gym profile lifecycle reuses `ArchiveDialog` verbatim** — `ArchiveDialogSubject` gains a third value, `'gym'`, with its own COPY entry, exactly the extension point that union type exists for. No new dialog component. See **Copywriting Contract**.
7. **The Equipment Availability Sheet's two actions are asymmetric in weight** (D-20): "Mark Unavailable" is the sheet's `PrimaryButton`; "My gym doesn't have this" is a lower-weight `text-accent` link beneath it, matching the Targets sheet's existing "Also update my program" precedent (Phase 5) for exactly the same session-vs-persistent asymmetry.

## Spacing Scale

Declared values (already shipped in `apps/mobile/tailwind.config.js`, multiples of 4 — inherited unchanged):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions inherited, still binding:**
- **48×48px minimum hit target** on every interactive element — every new Pressable this phase introduces (plate additions, machine cards' remove glyph, gym list rows, the Switch Gym rows, the Equipment sheet's actions) holds this floor.
- **The reserved plate-strip band (Phase 5 D-20) is exactly 40px when its content is passive/informational** — inherited, and this is the phase that fills it (Phase 5 explicitly deferred it here).

**New exceptions this phase introduces:**
- **The equipment/plate band grows past 40px, to a minimum of 48px, exactly when it renders a genuine tap target** — the not-loadable state's two correction values, or the zero-plates-configured recovery link ("Add plates"). This is the one place in the phase the reserved-band contract is knowingly exceeded, and it is exceeded for the same reason R4 exists everywhere else: a real touch target is never faked with `hitSlop` in this codebase (established precedent: `TextField`'s Show/Hide control comment), so a control that needs 48px gets 48px of real layout, and the band's height is what accommodates it — never the keypad grid, never the set rows above.
- **Dumbbell/plate "chips" in the Gym Profile Editor use the Exercise Strip's dashed-border "add" chip language** (Phase 5 §Exercise Strip) for their trailing "+ Add Weight"/"+ Add Plate" affordance — reused visual vocabulary, not a new one.

## Typography

Declared values (already shipped, inherited unchanged — this phase adds no fifth size and no third weight):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 20px (1.43) |
| Body | 16px | 400 (regular) — 600 (semibold) accepted for CTA/button text and populated values | 24px (1.5) |
| Heading | 20px | 600 (semibold) | 24px (1.2) |
| Display | 28px | 600 (semibold) | 34px (1.21) |

**Phase-specific role mapping:**
- Screen headings (Gym Profiles, New Gym, Edit Gym) → Heading, matching every other screen title in the app.
- Section headings inside the editor (Bars, Plates, Dumbbells, Machines & Cable) → Body, semibold, matching `DetailSection`'s existing convention verbatim (no new section-heading style).
- Equipment/plate band's bar-weight prefix ("20kg bar") → Label, `text-foreground-muted` — a quiet prefix per D-12, never competing with the plate numbers.
- Equipment/plate band's plate/pair/stack numerals (the actual figure) → Body, semibold — this is the band's populated value, held to the same weight Set Row gives a committed field value.
- Equipment/plate band's "Not loadable" label → Label, `text-foreground-muted`; the two tappable correction numbers beside it → Body, semibold, `text-accent` (interactive, emphasized — matches the Set Row "tap to autofill" precedent).
- Gym list row names → Body, regular (semibold only for the currently-active row, so "active" reads as a real visual distinction, not just a badge).
- Machine card names, plate/dumbbell values in the editor → Body, regular in form fields (via `TextField`'s existing input styling).

## Gym Profiles List

The Profile tab's new entry point (**Profile tab amendment**, see below) opens `apps/mobile/app/gym-profiles/index.tsx` — same top-level route-group shape as `apps/mobile/app/programs/library.tsx`, not nested under `(tabs)`.

**Layout:** mirrors Program Library's own structure exactly — a scrollable list, active gym pinned first (single-item "Active" partition, since only one gym can be active at a time, unlike programs' active/drafts/ready split), then the rest alphabetically, archived gyms in a collapsed trailing section identical to Program Library's archived partition. Each row: gym name (Body, semibold if active else regular), a muted Label subtitle summarizing the profile, joining **only the configured sections** in fixed order — bar → plates → dumbbells → machines ("20kg bar · 6 plate types" for a gym with no machines; omitted entirely when nothing is configured; "Archived" on an archived row). Absence is never rendered as a zero count or an "Incomplete" marker, since every section is legitimately optional (E2), and a trailing `•••` overflow trigger (48×48) opening **Gym Profile Action Sheet**.

**Gym Profile Action Sheet** (mirrors `RoutineActionSheet` verbatim — dynamic action list per row state, not a fixed constant): **Set Active** (omitted on the already-active row), **Edit**, **Duplicate**, **Archive** (or **Restore** on an archived row, destructive fill only in the Archive confirm dialog, never Restore's).

**New Gym CTA:** `text-accent`, "New Gym", top of the screen — matches Program Library's "New Program" placement and visual weight exactly (not a `PrimaryButton` fill; this list-level "add" action is consistently the lighter-weight text link across this app).

## Gym Profile Editor

`apps/mobile/app/gym-profiles/new.tsx` and `apps/mobile/app/gym-profiles/edit/[id].tsx` share one form component, `GymProfileEditor`, differing only in initial values and the write call — the same create/edit-share-one-form shape `exercises/new.tsx`/`exercises/edit/[id].tsx` already establishes.

**Layout, top to bottom, one scrollable form:**
1. **Name** — `TextField`, required.
2. **Unit system** — `SelectField`, two options (`kg` / `lb`), no placeholder-unselected state permitted past the seeded default (a profile always has a unit).
3. **Bar** (`DetailSection` heading "Bar") — the four preset chips (Copywriting Contract), then a `TextField` "Bar weight ({unit})" that the chips populate and manual entry can override.
4. **Plates** (`DetailSection` heading "Plates") — one row per denomination: a `TextField`-style weight value beside a stepper-driven count (reusing `ExerciseSlotRow`'s stepper anatomy verbatim: `-`/`+`, 48×48, floor 0), a trailing 48×48 remove glyph (`trash-outline`, destructive-colored) per row, then the dashed "+ Add Plate" chip (Exercise Strip visual language) beneath the list.
5. **Dumbbells** (`DetailSection` heading "Dumbbells") — a `flex-row flex-wrap` row of weight chips (mirrors `SelectField`'s chip anatomy, but every chip is always "selected"-styled since presence in the list *is* the selection), each with a small trailing `×` remove glyph, then the same dashed "+ Add Weight" chip.
6. **Machines & Cable** (`DetailSection` heading "Machines & Cable") — one `bg-surface rounded-md p-md` card per named entry: name `TextField`, an Available `ToggleRow` (reused verbatim from `profile.tsx`'s existing `ToggleRow`), and — only rendered while Available is on — stack min/max `TextField`s side by side, an increment `TextField`, and an optional "Starting resistance (optional)" `TextField`; a 48×48 remove glyph top-right of the card; a trailing "+ Add Machine" text-accent row beneath the card list.
7. **"Save Gym"** — `PrimaryButton`, full-width, pinned at the form's end (not sticky-floating — this form can be long; pinning it to the bottom of a fixed-height dock the way `NumericKeypad` does would fight the scroll, so it scrolls with the content like every other form in this app).

**Validation is structural, not inline** (R5, inherited): a stepper cannot go negative, a `SelectField` cannot have no selection past first load, weight `TextField`s accept only the same decimal input shape `TextField` already accepts elsewhere in this app (no new validation UI is introduced).

## Equipment / Plate Band

Fills `NumericKeypad`'s reserved band (Phase 5 D-20, `RESERVED_BAND_HEIGHT`). New component `PlateStrip`, mounted where the empty placeholder `View` currently sits — no relayout of the digit grid or stepper row below it.

**Content selection is driven by the current exercise's `equipment_type` (D-14):**

| `equipment_type` | Band content |
|---|---|
| `barbell`, `ez_bar` | Plate breakdown: bar-weight prefix (Label, muted) + descending per-side plate stack (Body, semibold), `" · "`-joined |
| `dumbbell` | Nearest available pair: `{weight}{unit} pair` (Body, semibold) when the typed value matches an available increment exactly; otherwise the not-loadable pattern below |
| `machine`, `cable` | Stack range + increment (+ base resistance if configured) — informational when the typed value falls within range and on-increment; otherwise the not-loadable pattern below |
| `kettlebell`, `bodyweight`, `band`, `medicine_ball`, `exercise_ball`, `foam_roller`, `other`, or no gym profile resolved yet | **Band collapses to 0 height** — no inventory model exists for these equipment types this phase, and an empty 40px band with nothing in it would read as a bug, not a deliberate absence |

**Not-loadable state** (D-13, applies to barbell/ez_bar/dumbbell/machine/cable alike): `Not loadable · {lower} ← → {higher}` — both numbers independently tappable (`text-accent`, Body/semibold), each writing its value into the weight field exactly as if typed (never auto-committing the set, never touching any other field). This is the one state where the band grows past 40px to hold real 48px tap targets (Spacing exceptions, above).

**Zero-plates-configured state** (barbell/ez_bar with an empty plate list on the active profile): `No plates configured · Add plates`, the link tappable and routing to that gym's Plates editor section — also a grows-past-40px state, same justification.

**A logged weight's band never recomputes against a changed profile** (D-11) — the band only ever renders for the *currently focused, uncommitted* field; once a set is checked off, its row's keypad (and therefore its band) is gone, so there is no surface on which a historical band could even attempt to redraw.

## Session Action Sheet — Equipment row

`SessionActionSheet`'s fixed action list (Phase 5 D-13, `SESSION_EXERCISE_ACTIONS`) gains a fifth entry, appended after `info` — never inserted, never reordered, matching this codebase's established additive-only convention for closed lists (D-06's own rule, applied here to a UI constant instead of a vocabulary):

```
{ id: 'equipment', label: 'Equipment', icon: 'construct-outline' }
```

**Rendered exactly when the current exercise's `equipment_type` resolves to non-collapsed band content** (the same predicate the Equipment/Plate Band uses — one shared source of truth, not two divergent "does this exercise have equipment" rules). For bodyweight/kettlebell/band/etc. exercises the row is absent, not disabled — this is a structural exclusion by exercise type, not a "sometimes hidden" state, and is stated here explicitly rather than left implicit (mirrors Phase 5 R10's discipline of never leaving a mode/condition unstated).

Selecting it opens **Equipment Availability Sheet** for the resolved equipment implicated by the current exercise (a named machine for `machine`/`cable`; "Barbell" for `barbell`/`ez_bar`; the specific weight for `dumbbell`).

## Equipment Availability Sheet

New component, same overlay/`ScrollView`/`max-w-[400px]`/`rounded-md bg-surface p-lg` shape every sibling sheet in this app uses (`SessionActionSheet`, `RemoveExerciseDialog`, `ReorderExercisesSheet`).

**Layout:**
1. Heading + body from the Copywriting Contract.
2. **"Mark Unavailable"** — `PrimaryButton`, session-scoped (D-20), immediate — no further confirmation, since this write is low-cost and fully reversible within the session (nothing is destroyed; it is subtracted from D-21's resolved inventory for this session only).
3. **"My gym doesn't have this"** — `text-accent`, no fill, beneath the primary button — opens a confirmation dialog (ArchiveDialog-shaped, neutral confirm, no destructive fill) before writing through to the profile.
4. **After either action:** the sheet transitions in place to show alternatives — reuses `SwapSuggestionList` verbatim, headed by "This exercise is unavailable right now" (Copywriting Contract). Tapping a candidate performs the existing session-only swap (D-22/D-23, Phase 5's Swap mechanism), carrying the original's targets across, and closes the sheet.
5. **"Cancel"** — dismisses with no change, same geometry as every sibling sheet's Cancel row.

## Session Menu — Switch Gym row

The session `Menu` popover (Phase 5 Amendment A.2, currently Pause/Resume · Session Note · Discard) gains a fourth row, **Switch Gym**, inserted between Session Note and Discard — Discard stays last and `text-destructive`, so the destructive action is never adjacent to a newly-added benign one (same rule Amendment A.2 itself already states for Session Note's placement).

Selecting it closes the menu, then opens **Switch Gym Sheet**: a vertical list of the user's non-archived gyms (name, Body — semibold + `text-accent`/`border-accent` on the currently-active row with a trailing "Active now" Label), each a 48×48-minimum row. Tapping a non-active row restamps the session's gym immediately (D-18) — no confirmation step, since D-18 already establishes this as reversible and non-destructive to any already-logged set (D-11). A trailing **"Manage Gyms"** link (`text-accent`) routes to the Gym Profiles list.

**Modes:** `live` only, identical scoping to Session Note (Amendment A.2) — the Menu itself only renders in `live` mode.

## Phase-Wide Rules

Extends Phases 1–5's R1–R10 (all still binding). This phase adds:

- **R11 — The equipment/plate band's content predicate is one named function, read by both the band and Session Action Sheet's Equipment row.** Two independently-computed "does this exercise have resolvable equipment" checks are exactly the kind of drift D-21 already warns against for the resolved-inventory function; this rule extends that discipline to this phase's one new UI-only predicate.
- **R12 — A logged set's band never redraws.** Mirrors D-11 structurally at the UI layer: the band only exists for the currently-focused, uncommitted keypad field; there is no code path that renders a band against a completed row.

### E2 — Gym Profile Editor

*Element kinds:* `form`, `list-collection`, `interactive-control`, `static-content`

| State | Verification | Contract |
|-------|--------------|----------|
