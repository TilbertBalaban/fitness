<objective>
Establish the styling and appearance system every remaining screen in this project inherits, and deliver
PLAT-09 as a working, persisted, three-state control.

CONTEXT.md left the styling foundation to Claude's discretion but flagged it as high-leverage — inherited
by all eleven remaining phases — and asked for a real evaluation. `01-RESEARCH.md` performed it and
selected NativeWind v4 over Unistyles (requires Nitro Modules native code and cannot run in Expo Go,
forcing an EAS dev-client build a phase earlier than PowerSync actually requires one) and over Tamagui
(compatible, but a compiler and design-system surface disproportionate to a bootstrap phase). This plan
implements that selection along with the UI-SPEC's binding token contract.

Purpose: every later screen gets colour, spacing, and typography tokens instead of re-deriving them, and
the appearance decision is made once rather than in each phase.
Output: a working Appearance control, a token system, and light/dark that survives a restart.
</objective>
