<objective>
Complete the auth surface D-06 scopes for this phase by delivering password reset end-to-end: a mailer
port in NestJS with two interchangeable adapters (D-08), and a reset page hosted on the project's own web
build rather than behind a native deep link (D-07).

D-07's whole point is that the reset link opens a browser on every platform, so there is no Apple
associated-domains file, no Android intent filter, and no custom dev-client rebuild needed to exercise the
flow — and the behaviour is identical from all three clients because it never leaves the browser. D-08's
whole point is that cloning this repository must never require owning a domain or a provider account to
run the app, so local development captures mail in an SMTP catcher and a real provider is selected by
environment variable when deployed.

Purpose: the last of the four auth operations D-06 admits (sign-up, sign-in, sign-out, password reset)
becomes real, and the seam that keeps outbound mail provider-agnostic is set now rather than retrofitted.
Output: a clickable reset flow that works from a fresh clone with no external account.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
