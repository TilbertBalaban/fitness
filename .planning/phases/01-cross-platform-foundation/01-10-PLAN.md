## Flagged assumptions (probe-surfaced)

This plan owns two of the six edge-probe rows; `01-09-PLAN.md` owns the other four. Both are carried
forward as flagged assumptions rather than turned into new work, because both bear only on PLAT-09,
which `01-VERIFICATION.md` already records as VERIFIED. Neither is dropped.

- **PLAT-09 (`boundary`) — "What happens exactly at each min/max/threshold, and one step either
  side?"** The only real threshold on the appearance requirement is the React Native minor version at
  which the resume-OS sentinel changes value: below it the sentinel is the legacy null, at and above
  it the sentinel is the string form. WR-02's fix in Task 1 pins the test to the side of that
  threshold this project actually ships on. **Assumption:** no other threshold exists on PLAT-09 —
  the appearance token set is a closed three-member enumeration with an unknown-value fallback
  already covered by an existing test, and there is no numeric or temporal boundary in the feature.
  If the developer disagrees, the place to add coverage is Task 1's behavior block.
- **PLAT-09 (`precision`) — "Where can precision loss, overflow, or rounding occur, and what is the
  exact contract?"** **Assumption:** none applies. The appearance feature stores and reads a
  three-member string token; there is no numeric value anywhere in its path to lose precision, and
  no accumulation that could overflow. Recorded rather than silently dismissed, per the no-drop rule.

**Canon referral (prohibition probe).** Account-enumeration hardening as a general class is canon —
covered by `/gsd-secure-phase`; the bespoke prohibition kept here is narrower and specific to this
task: that the *restructuring* must not move the disclosure line the UI-SPEC deliberately drew.
