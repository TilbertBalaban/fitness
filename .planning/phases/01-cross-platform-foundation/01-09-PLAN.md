<objective>
**As a** person who signed in on my phone, **I want to** tap Sign Out and have the session
genuinely end on the server — not just on my device — **so that** a lost or stolen phone cannot keep
using an account I already signed out of.

This plan closes both failed truths from `01-VERIFICATION.md`. They share one root cause and one
consequence: `apiFetch` — the sole shared request path — never presents the session credential on
native, so the server cannot tell which session is talking to it. Explicit sign-out sends an
unauthenticated request the server cannot act on (the Postgres row survives indefinitely while the
client believes it signed out), and the background revocation check receives an unauthenticated
answer it can never read as a revocation.

Two findings from reading the installed packages reshape the fix, and neither is in `01-REVIEW.md`
or `01-PATTERNS.md` — both of which were written without `node_modules` available:

**Finding A — the stored cookie is not a header string.** `@better-auth/expo@1.6.26` stores a JSON
map of cookie entries under the `_cookie` key, wraps storage in a chunking adapter that may split a
large value across numbered sibling keys behind a marker prefix, and exposes the plugin action
`getCookie()` which reassembles chunks, drops expired entries, and serializes the result into a real
header string. `01-REVIEW.md`'s proposed fix — read the `_cookie` key from secure storage and use its
raw value as a header — would attach a JSON blob, or a chunk marker, and would not work. The
credential must come from the plugin's own action, not from a hand-rolled read.

**Finding B — attaching the credential is necessary but NOT sufficient for truth #6.** Better Auth's
get-session route answers an unknown or deleted session with HTTP 200 and a null body — it does not
return 401 with a revocation reason. So even with a credential attached, `classifyAuthOutcome`
returns `ok` and `isRevocation` stays false forever. Truth #6 needs a second, narrow change: a
session probe that treats *a completed round trip that authoritatively reports no session, while we
did present a credential* as the positive server revocation response D-01 describes. The
"while we did present a credential" half is load-bearing, not decoration — without it a transient
secure-storage read failure would sign the user out, which is precisely what D-01 forbids.

**Scheduling note:** `depends_on` is deliberately empty. Plans 01-01 through 01-08 are already
executed and committed; this plan's wave is 6 because waves 1-5 are history, not because anything
pending blocks it. `01-10-PLAN.md` also runs in wave 6 — the two share no modified file.

Purpose: PLAT-06 and the D-01 half of the session contract that ends a session, plus the PLAT-01
platform asymmetry — the identical user action already works correctly on web and silently does not
on native.
Output: a sign-out that ends the session on every platform, and a revocation mechanism that can
actually fire.

  parallel, what is guaranteed?" applied to sign-out racing the background probe. Task 3 tests it.
  Note these two rows are tagged PLAT-05 by the probe but are answered in the session-lifecycle
  domain this plan owns, which is why this plan's `requirements` field does not claim PLAT-05.
- **PLAT-01 (`unclassified`) — carried forward as a flagged assumption, not new work.** The probe
  could not assign an edge category. The planner's reading is that PLAT-01's edge axis is *platform
  asymmetry*: the same user action taking a different path on each target. This plan closes the one
  known asymmetry in the transport layer (credential attachment) and proves it over HTTP.
  **Assumption:** no further undiscovered transport-layer asymmetry exists between the web and native
  request paths beyond the credential one. The residual PLAT-01 risk is render parity on iOS and
  Android, which is not a transport concern, is explicitly out of scope here, and is addressed as a
  human-verification affordance in `01-10-PLAN.md` Task 3.

encryption are canon OWASP/ASVS V3 items covered by `/gsd-secure-phase`; not minted as bespoke
