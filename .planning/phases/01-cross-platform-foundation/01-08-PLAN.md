    Complete `turbo.json` so `typecheck`, `lint`, and `test` are cacheable tasks with their proper input
    globs, and `test:e2e` is marked non-cacheable because its result depends on a live database rather than
    on file inputs alone.

    Write `.github/workflows/ci.yml` triggered on push and pull_request, with two jobs.

    The `check` job installs pnpm and Node 22, restores the pnpm store from cache, runs `pnpm install
    --frozen-lockfile`, then `pnpm turbo run typecheck lint test`. The frozen-lockfile flag matters: it
    fails the run when the lockfile and the manifests disagree, which is the cheapest place to catch a
    dependency that was added without being committed.

    The `e2e` job declares a `postgres:17` service container with a health check, sets `DATABASE_URL` to
    point at it, supplies the remaining variables the API needs to boot with throwaway values generated in
    the workflow rather than drawn from repository secrets — nothing this phase tests needs a production
    credential, and referencing one would put a real secret in a log-bearing environment for no benefit.
    It runs `pnpm --filter api db:push` to apply the Drizzle schema to the fresh service database, then
    `pnpm --filter api test:e2e`, which exercises the sign-up and session specs, the schema-parity gate, the
    password-reset flow, and the version-floor rejection.

    For the reset flow, run the mail catcher as a second service container on port 1025 so the end-to-end
    spec's mailer path is the same one it takes locally rather than a CI-only substitute.

    Every test invocation must run once and exit; no job may pass a watch flag, or the runner will hang
    until it times out rather than reporting a result.

    Add no EAS Build job. This phase runs entirely inside Expo Go, there is no dev-client to build, and the
    first thing that structurally requires one is Phase 2's native SQLite module.

    Record in `README.md` under a "Continuous integration" heading which jobs run on push and how to
    reproduce each one locally.
  </action>
