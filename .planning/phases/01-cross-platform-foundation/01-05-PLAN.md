<objective>
Implement the offline session policy the whole project's core value rests on: a person walks into a gym
with no signal, opens the app, and it works — signed in, immediately, with no network on the launch path
and no possibility of being signed out by a network that simply is not there.

This plan is where D-01, D-02, D-03, and D-04 become code. `01-RESEARCH.md` Pitfall 2 is the trap to avoid:
Better Auth's server-side `expiresIn` and `updateAge` are not the mechanism for D-01 and never were. Plan
01-01 set them generously so the server does not independently expire a session the client is still
honouring, but the actual decision — "a refresh request that could not reach the server is not the same
event as a refresh request the server rejected" — is a branch in this project's own client code, and it
does not exist until this plan writes it.

`01-RESEARCH.md` Pitfall 1 is the second trap: the Better Auth Expo plugin's cached-session read is a
native-only code path with an early return on web, where the browser's cookie jar carries the session
instead. So D-02's "render immediately from a synchronous local read" is a native guarantee, and the web
equivalent is structurally different and simpler. The UI-SPEC's §"Session & Loading States" table encodes
both treatments; this plan implements both rather than forcing one code path onto two mechanisms.

Purpose: PLAT-06 and roadmap success criterion 2, and the structural defence against the Clerk-style
offline black screen research flagged as disqualifying.
Output: a session that survives airplane mode, a multi-week gap, and a hostile captive portal.
</objective>
