<objective>
Stand up the Walking Skeleton: one pnpm/Turborepo workspace in which a person can create an account
from the Expo app on iOS, Android, and a desktop browser, and land on a screen showing the email the
NestJS API returned for their new session — a real row written to Postgres through Drizzle, a real
session read back over a version-prefixed HTTP route.

This is the phase's tracer. It touches every layer Phase 1 will modify — workspace, NestJS bootstrap,
API versioning, Drizzle/Postgres, Better Auth server, Better Auth Expo client, Expo Router UI — on
exactly one happy path. It is production-quality, not a prototype: the code written here stays and is
expanded by plans 01-02 through 01-08. Nothing is stubbed in a way that would require an architectural
change to fill in.

Implements D-05 (Better Auth self-hosted), the auth-surface floor of D-06 (sign-up and sign-in; the
remaining surface arrives in 01-04 and 01-06), and the URI-versioning half of success criterion 4.

Purpose: prove the whole stack works end-to-end on the agent's best early-context tokens, so an
architectural dead end surfaces after one commit rather than after ten.
Output: a running full stack — `pnpm dev` brings up the API and the Expo app; an account created on
one client signs in on the others.
</objective>
