**`apps/mobile/lib/catalog/exercise-detail.ts` (new).** Export `loadExerciseDetail(db, id)`
returning `ExerciseDetail | null`, plus `sortMuscleTargets(targets)` as a separately-exported pure
function so the ordering contract is unit-testable without a database.

`ExerciseDetail` carries the exercise row's fields plus `primaryMuscles: MuscleTarget[]` and
`secondaryMuscles: MuscleTarget[]`, where `MuscleTarget` is
`{ muscleGroupId, name, bodyRegion, weightFactor }`. Keep `weightFactor` as the stored exact
string on the type and parse it only inside the comparator — the schema's decimal-as-exact-string
rule exists so a decimal never round-trips through a binary float, and a `parseFloat` on the way
out of the loader would reintroduce exactly that.

The join is one query, not three: `exercise` LEFT JOIN `exercise_muscle_mapping` LEFT JOIN
`muscle_group`, filtered by the exercise id, then grouped in memory by role. PITFALLS.md §13 names
"exercise + muscle mappings + images" as the canonical N+1 shape in this project, and a
per-mapping muscle-group lookup is that shape.

`sortMuscleTargets` orders primary before secondary, then `Number(weightFactor)` descending, then
muscle group name ascending. The third key is what makes the order total rather than merely
deterministic-in-practice, so a re-render over identical data cannot reorder the list.

Normalize absent optional fields on the way out: `cue_text` and `instructions_text` to `null`,
`aliases` and `image_urls` to `[]`. The screen then branches on emptiness rather than on three
different shapes of absence, which is what makes the "omit the section entirely" rule a single
condition instead of a chain.

Return `null` for an unknown id. The screen turns that into a not-found state; throwing would put
error handling in the wrong layer.

`null` when the children are empty, absent, or an empty string. This is the mechanism behind

**`apps/mobile/components/MuscleTargetList.tsx` (new).** Renders the ordered primary targets as

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route parameter -> local query | An arbitrary `[id]` segment reaches a database query |
| seeded and user-authored text -> RN render tree | Third-party dataset text and a user's own custom-exercise text render on the same screen |
| remote image URL -> `<Image source={{uri}}>` | If images ever ship, an external URL is loaded by the client |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-29 | Tampering | `[id]` route parameter | medium | mitigate | The id reaches Drizzle as a bound parameter through `eq(exercise.id, id)`, never string-interpolated into SQL. An unknown id returns `null` and renders a not-found state rather than surfacing a database error to the user. |
| T-03-06 | Tampering | custom-exercise `name`, `cue_text`, `instructions_text` rendered on the detail screen | low | mitigate | All three render into RN `<Text>` only — never `dangerouslySetInnerHTML`, never a WebView — so HTML injection is not reachable by construction on native, and the `pnpm --filter mobile build` web export is where the same property is confirmed for React Native Web. |
| T-03-30 | Information Disclosure | detail screen network behavior | high | mitigate | The screen and its loader import no fetch primitive at all, asserted by a grep acceptance criterion. This is the offline guarantee PROJECT.md's core value rests on; a single stray fetch would silently undo the whole delivery mechanism. |
| T-03-31 | Denial of Service | muscle-mapping load | medium | mitigate | One joined query per exercise rather than a per-mapping muscle-group lookup — PITFALLS.md §13 names this exact nested shape as the project's canonical N+1 risk. |
| T-03-32 | Spoofing | remote image URL loaded into `<Image>` | low | accept | `image_urls` is empty for every seeded row under COVERAGE.md's current opt-out, so no external URL is loaded in v1. If the images decision is reversed at 03-04 task 1, this row is re-rated and an allowed-host check becomes required. |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package. |
