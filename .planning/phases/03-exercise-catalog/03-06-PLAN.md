**`apps/mobile/lib/catalog/search-index.ts` (new).** Export `buildSearchIndex(exercises)` wrapping
MiniSearch, `normalizeQuery(raw)` and `searchCatalog(index, query, exercises)`.

`normalizeQuery` is the encoding contract: `String(raw ?? '')`, Unicode-normalize to NFC, lowercase,
strip combining diacritical marks, and collapse whitespace. Apply the identical normalization to
the indexed fields via MiniSearch's `processTerm` option so query and document go through one
function — two normalizations is how case- or accent-insensitivity silently stops holding for one
side. Comparisons are over normalized code points; nothing in this module compares byte lengths.

Index `name` and `aliases`, with `name` weighted above `aliases`. Enable prefix matching and
MiniSearch's fuzzy tolerance at a low threshold — enough for a transposed letter, not enough to
return a leg exercise for a chest query.

`searchCatalog` returns the full exercise list when the normalized query is empty (this is the
EXER-01 empty-input contract, and it belongs here rather than in the screen so it is unit-testable),
and otherwise returns MiniSearch's hits mapped back to exercises, each carrying its score.

**`apps/mobile/lib/catalog/catalog-filter.ts` (new).** Export `CatalogFilters`
(`{ muscleGroupIds: string[], equipment: string[], movementPatterns: string[] }`),
`deriveFacets(exercises, mappings)`, `applyCatalogFilters(exercises, mappings, preferences, filters, userId)`
and `sortCatalogResults(scored)`.

Filter semantics, stated so they are not inferred: **AND across dimensions, OR within a
dimension.** An empty array for a dimension means that dimension is inactive, which is the same
result as selecting all of its values — assert both directions, since only asserting one lets a
subtle off-by-one in the "all selected" branch pass.

Archive exclusion is part of the filter, not a caller responsibility: exclude any exercise with a
`user_exercise_preference` row for the current user whose `archived_at` is non-null. One code path
for every exercise regardless of origin, seeded or custom — PITFALLS.md §11 is explicit that
archive-logic bugs are a top corruption risk, and two code paths is how they arrive.

`sortCatalogResults` defines the stable total order: relevance score descending, then name
ascending using a locale-aware comparator over the normalized name, then id ascending. The id tie-
break is what makes the order *total* rather than merely deterministic-in-practice, so a re-render
over the same data can never reorder rows.

`deriveFacets` returns, per dimension, the distinct values actually present in the catalog, sorted
for stable chip order, and omits a dimension whose value set is empty so the screen has nothing to
decide.

Neither module reads the database or imports React. They take plain arrays and return plain
arrays, which is what makes every case in `<behavior>` a fast unit test rather than a rendered one.
  </action>
