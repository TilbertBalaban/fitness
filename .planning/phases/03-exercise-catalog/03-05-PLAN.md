<objective>
**As a** lifter who installed the app months ago and finally has signal in the car park,
**I want to** the catalog to quietly catch up to whatever the project has corrected since,
**so that** my custom exercises survive untouched and I never wait on a download to look
something up.

This plan puts the ~900 normalized rows into Postgres, ships the identical artifact as the
bundled device snapshot, and adds the only new REST surface this phase is allowed: the read-only
`ExerciseCatalogModule`. That module is D-01's explicit carve-out — ordinary REST endpoints are
reserved for auth, media upload URLs and the catalog download — and it stays read-only, which is
what keeps ARCHITECTURE.md's "two write paths for the same data" anti-pattern from recurring
inside this phase.

Purpose: make the full catalog real on both sides, and make an update reach an existing install
without clobbering anything the user authored.
Output: a seed script, the catalog module, the bundled snapshot, a background refresh path, and
an e2e spec covering the version handshake.
</objective>

**`apps/api/src/seed/seed-catalog.ts` (new).** A plain Node script in `generate-corpus.ts`'s
shape: the same dotenv bootstrap lines, `import { db, pool } from '../db/drizzle.module'`, no
`@Injectable()`, no Nest bootstrap. Export `seedCatalog(db, snapshot)` as the testable unit and
keep `main()` a thin read-call-exit wrapper that closes the pool.

Validate the artifact with `isCatalogSnapshot` before opening a transaction; abort with a
non-zero exit on failure rather than writing a partial catalog.

Inside one transaction:
1. Upsert every `muscle_group` row on `id`.
2. Upsert every `exercise` row on `id`, setting `is_custom` false, `user_id` null, `source` the
   literal `seed`, and a fresh `nextval('sync_seq')` for `serverSeq`. The `onConflictDoUpdate`
   `set` must **not** include `archived_at` — re-seeding must not silently un-archive a row the
   previous step archived.
3. Delete-then-insert `exercise_muscle_mapping` rows scoped to the seeded exercise ids only, so a
   changed mapping set converges rather than accumulating stale rows.
4. Archive drift: select every `exercise` row where `source = 'seed'` and `archived_at IS NULL`
   whose id is not in the artifact, and stamp `archived_at`. Never `DELETE` — a seeded row can be
   referenced by `personal_record` and `session_exercise`, both `notNull`, and PITFALLS.md §11
   names the hard delete with no reference check as the warning sign to design against.

Every statement must be scoped so it can only touch rows where `source = 'seed'` and
`user_id IS NULL`. A user's custom exercise is never in the seed's blast radius, and the test
asserting a pre-existing custom row is unchanged is what proves it.

Batch the inserts (chunks of a few hundred) rather than issuing ~900 individual statements —
`seeded-corpus-perf.e2e-spec.ts` establishes this codebase's standing objection to per-row query
shapes.

**`apps/api/package.json`.** Add `"seed:catalog": "ts-node src/seed/seed-catalog.ts"`.

**`apps/api/src/catalog/catalog.service.ts` (new).** Loads
`apps/api/src/seed/data/catalog-normalized.json` **once at construction** and holds it in memory —
the artifact is a build-time constant, so re-reading it per request buys nothing and reading it
from Postgres would make an unauthenticated endpoint issue database queries. Expose `getVersion()`
returning `{ catalog_version }`, `getSnapshot()` returning the parsed artifact, and `getEtag()`
returning a quoted strong ETag derived from `catalog_version` (the version is already a content
hash, so the ETag needs no second digest). Follow `sync.service.ts`'s `@Injectable()` shape;
unlike it, this service injects nothing.

**`apps/api/src/catalog/catalog.controller.ts` (new).** `@Controller('catalog')` — a normal
versioned path, **not** `VERSION_NEUTRAL`, because the catalog does want `/v1/` versioning and
`MinClientVersionGuard` coverage, unlike health. Carry `@AllowAnonymous()`, with a comment stating
why: the payload is public seeded content with no user data in it, and requiring a session would
mean a cold-started client could not refresh its catalog before signing in. Two `@Get()` handlers
only — no mutation verb exists on this controller, and that is the property that keeps
ARCHITECTURE.md's Anti-Pattern 1 intact for `exercise`.

For the download handler, read `If-None-Match` off the request and compare it to `getEtag()`;
on a match, set status 304 and return no body. On a miss, set the `ETag` and
`Cache-Control: public, max-age=0, must-revalidate` headers and return the snapshot. This is the
T-03-04 mitigation: without it, an unauthenticated endpoint re-serves a multi-hundred-kilobyte
payload on every app launch.

**`apps/api/src/catalog/catalog.module.ts` (new).** `@Module({ controllers: [CatalogController], providers: [CatalogService] })` —
as narrow as `HealthModule`. No `exports` unless a later consumer needs the service; keep it
self-contained.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet -> `GET /v1/catalog/*` | The only anonymous non-health route this project exposes |
| server response -> local SQLite | A downloaded payload is written into the database that also holds the user's training data |
| seed script -> Postgres | A build-time script writes directly, bypassing every application-level validator |
