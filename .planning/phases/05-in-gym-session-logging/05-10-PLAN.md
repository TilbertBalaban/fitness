## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-chosen date → `timezone` / `local_date` | A user-supplied calendar day rewrites two columns every downstream read path treats as stamped-once |
| editing-mode screen → live-session write paths | A past-tense surface writes into the same tables the live screen owns |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10-01 | Tampering | `setSessionDate` | high | mitigate | The three columns move as a unit through one function that derives the calendar pair from `captureCalendarDay`, so a session can never be attributed to one day and sorted under another. Pinned by the single-writer source assertion and the cross-timezone unit case (PITFALLS §12). |
| T-05-10-02 | Tampering | editing-mode write paths | high | mitigate | The editing subtree cannot reach `scheduleRestAlert` or `shouldAutoAdvance` because neither is imported into it, so no past-tense edit can schedule a live alert or move a live pager. Pinned by the import-absence source assertion and the DOM assertion in the e2e (D-32, Pitfall 3). |
| T-05-10-03 | Repudiation | backdating a session | low | accept | RESEARCH's security domain records this explicitly: a single-user personal training log is not a multi-tenant leaderboard, and backdating benefits only the user's own derived metrics. No mitigation beyond what already exists is warranted, consistent with this project's exclusion of social and competitive features. |
| T-05-10-04 | Elevation of privilege | editing a session by route parameter | high | mitigate | `loadSessionTree` resolves the session through the user-scoped read path, and the server's apply path re-resolves ownership from the authenticated session on every push, so a route parameter naming another user's session id yields no readable rows and no writable ones (ASVS V4). |
| T-05-10-05 | Information disclosure | History and editing reads | medium | mitigate | Every read is scoped by the authenticated user id and by the PowerSync sync rules' `auth.user_id()` filter; no new unscoped read path is introduced. |
</threat_model>
