## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

Declared values (already shipped in `apps/mobile/tailwind.config.js`, multiples of 4 — inherited unchanged):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions inherited, still binding:**
- **48×48px minimum hit target** on every interactive element — this phase is the densest test yet under time pressure: the checkmark, the keypad's digit keys and steppers, the exercise-strip chips, the header timer's tap-to-expand rest control, the action bar's three buttons, and the overflow `⋮` all hold the floor. This is not a nice-to-have this phase — D-13/pitfall 7 name one-handed, thumb-only operability as the acceptance bar.

**New exceptions this phase introduces:**
- **The `NumericKeypad`'s digit keys are fixed at 56×56px, not the 48px floor.** The keypad is the single highest-frequency interaction surface in the whole app (every set, every field) and is used one-handed under time pressure mid-set; the extra 8px per key reduces mis-taps measurably more than the floor requires. This applies only to the keypad grid — every other control in this phase holds the standard 48×48 floor.
- **The reserved plate-strip band above the keypad (D-20) is a fixed-height, always-rendered empty `View`, height 0 content but not height 0 layout** — exactly 40px, empty in this phase, so Phase 6 fills it without a relayout. It participates in spacing like any other element (no visual chrome, no border, no background — a true placeholder, not a visible empty box).
- **The greyed reference value beside each field has no minimum width of its own** — it grows with its own text length exactly like the field it sits beside (R4 wrap-and-grow, inherited from Phase 4), never truncates, never forces the field it annotates to shrink.

## Typography

Declared values (already shipped, inherited unchanged — this phase adds no fifth size and no third weight):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 (regular) | 20px (1.43) |
| Body | 16px | 400 (regular) — 600 (semibold) accepted for CTA/button text, matching `PrimaryButton` | 24px (1.5) |
| Heading | 20px | 600 (semibold) | 24px (1.2) |
| Display | 28px | 600 (semibold) | 34px (1.21) |

**Phase-specific role mapping:**
- Exercise name in the pager header, workout summary title, "Workout in progress" banner heading → Heading.
- Header timer readouts (duration, rest countdown) → **Display**, semibold — the single phase-specific escalation: these two numbers are the thing the user's eye returns to constantly across a 30–90 minute session, and they must be legible at a glance without focusing, including one-handed and mid-lift.
- Set row field values (weight/reps/RIR entry) → Body, semibold when populated (visually distinguishes an entered value from its placeholder), regular for the placeholder state.
- Greyed reference values ("last time: 60kg") → Label, `text-foreground-muted`, never Body — they must read as secondary at a glance, not compete with the field itself.
- Exercise strip chip labels (set-count fraction, e.g. "3/4") → Label.
- Numeric keypad digit glyphs → Display, so the largest, most frequently misread character on the busiest control in the app is unambiguous even glanced at peripherally.
- Action bar button labels (Warm-up, Targets, Note) → Label.
- Workout summary section headings ("Muscles Trained", "Per-Exercise Breakdown") → Body, semibold, matching Phase 3's section-header convention.
- Per-exercise breakdown rows (sets/reps/weight/volume/e1RM) → Body, regular; PR badge text → Label, semibold, accent-on-accent-tint (see Color).
- Empty/error state headings → Heading; their body copy → Body, regular, `text-foreground-muted`.

## Color

Declared values (already shipped in `apps/mobile/global.css`, inherited unchanged):

| Role | Value (light) | Value (dark) | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `#FFFFFF` | `#09090B` | Screen background |
| Secondary (30%) | `#F4F4F5` | `#18181B` | Cards, rows, chip fills, the header timer bar background |
| Accent (10%) | `#2563EB` | `#3B82F6` | See extended reserved-for list below |
| Destructive | `#DC2626` | `#EF4444` | Destructive actions only — Discard Workout, Delete Workout, Remove Exercise |
| Foreground (primary text) | `#09090B` | `#FAFAFA` | Body/heading text on Dominant or Secondary |
| Foreground (muted text) | `#71717A` | `#A1A1AA` | Labels, helper text, greyed reference values, unselected chip content |

**Accent reserved for** (Phase 1's list, extended additively by Phase 3/4 and now this phase — never widened to "all interactive elements"):
- Primary CTA button fill (unchanged: Start Workout, Finish Workout, Add Exercise, etc.)
- Active tab bar icon + label (unchanged)
- Text link color (unchanged)
- Focused input field border, active filter-chip border (unchanged, Phase 3/4)
- **New this phase:** the currently-active chip in the exercise strip (border + fill tint), and the checkmark's fill once a set is completed.
- **New this phase:** the keypad's next/submit arrow key.
- **New this phase:** the "tap to autofill" affordance on a greyed reference value — rendered as an accent-tinted underline beneath the muted text, the one place accent touches Label-role text, because this is a live interactive control (LOG-04) disguised as static reference text and must read as tappable.
- **New this phase:** PR badge fill in the workout summary (accent-tinted background, accent text) — a PR is the single most rewarding moment in the summary and is the one place this phase spends its 10% on celebration rather than function; there is no separate "gold" or "trophy" hue introduced (see below).

**No second semantic color is introduced beyond the existing Destructive.** PRs are drawn in accent, not a new "success/gold" hue — the design contract reserves a second semantic color for destructive actions only, and a personal record is not a warning-adjacent state that needs its own hue; it is the accent system doing its normal "this is the thing to notice" job at higher visual weight (badge fill vs. the usual border/text-only accent usage).

**Rest-timer warning-state color — resolved here, not a new hue.** The rest countdown's numerals stay `text-foreground` at all times; there is no red/amber countdown-anxiety treatment. Rationale: D-26 already defines rest as stopping and clearing at zero with no overtime count-up, so there is no "you're over time" state to warn about, and introducing urgency color on a countdown a lifter is deliberately not staring at (the whole point of a backgroundable timer) would only matter in the one moment it's visible, which is exactly when the number reaching zero is already the signal.

## Header Timer Bar (D-24)

A persistent, non-scrolling bar pinned above the exercise strip, present on every state of the active-workout screen except `editing` mode (D-32 — the edit-mode screen shows the session's date instead, see **Session Modes** below).

**Layout:** two columns, `flex-row justify-between`, `bg-secondary` background, `md` (16px) horizontal padding, `sm` (8px) vertical padding.
- **Left column — workout duration**, counting up. Label above ("Workout" — Label, muted), the running `MM:SS`/`H:MM:SS` readout below (Display, semibold, `text-foreground`).
- **Right column — rest timer**, counting down, mirrored alignment (right-aligned text). Label above ("Rest" — Label, muted), the running `MM:SS` readout below (Display, semibold, `text-foreground`). **Dormant-but-present between sets (D-24):** when no rest is active, the readout shows `0:00` in `text-foreground-muted` rather than being hidden or replaced with placeholder text — the column's position and size never change between dormant and active, so nothing shifts under a thumb reaching for the exercise strip below it.
- Tapping the right column (whole column is the hit target, not just the number) opens **Rest Timer Full-Screen**. Tapping the left column does nothing (duration is informational only, not interactive).
- **Paused state:** the left column's label changes to "Paused" (still Label, muted) and the readout freezes at its value when pause was pressed, rendered in `text-foreground-muted` instead of `text-foreground` — the one visual cue distinguishing a frozen clock from a running one besides the literal number not changing.

## Rest Timer Full-Screen (D-10/LOG-10)

Opened by tapping the header bar's rest column. A modal/full-screen route, not a bottom sheet (the countdown deserves the whole screen the way MacroFactor's own full-screen rest view does — this is the one moment in the session where nothing else needs to be visible).

- **Large centered countdown** — the numeral itself renders at a size larger than any other numeral in the app (a one-time exception, not a new typography role: `fontSize: 64`, semibold, `text-foreground`), because this is the one screen whose entire purpose is that number.
- Two controls beneath it, each a 48×48-minimum `Pressable`, side by side: **"+30s"** (extends, D-27) and **"Skip Rest"** (cancels, D-27). Both are Body-role, semibold, `text-accent` text on `bg-secondary` fill — secondary-weight buttons, not the primary CTA fill, since neither is "the" action of this screen the way Finish Workout is on the main screen.
- A dismiss control (`✕`, top-left corner, 48×48, `useThemeColors()`-resolved) returns to the workout screen without altering the timer — the countdown keeps running identically whether this screen is open or not (D-21's stored-timestamp model makes this free).
- **At zero:** the countdown reads `0:00`, the screen does not auto-dismiss (the user chooses when to leave), and the "+30s"/"Skip Rest" pair is replaced by a single full-width **"Back to Workout"** primary-CTA-styled button, since there is nothing left to extend or skip once rest has already ended.

## Exercise Strip (D-12)

A horizontally scrolling row of chips pinned beneath the header timer bar, one chip per exercise in session order: reuses `CycleStrip`'s visual language (Phase 4 §Cycle Strip) — same chip anatomy, same 48×48 floor, same horizontal-scroll-never-wrap rule.

**Chip anatomy (resolved here — D-12 fixed content, not layout):**
- Two-line chip: exercise name (Label, single line within the chip but the *chip* widens rather than truncating the name per R4 — see Phase-Wide Rules) on top, completion fraction (`3/4`, Label, muted) beneath.
- **Current chip:** `border-accent`, `bg-surface`. **Completed chip** (all sets checked): `border-foreground-muted`, `bg-secondary`, fraction text renders as a checkmark glyph instead of "N/N" (e.g. `4/4` becomes a single ✓, `Ionicons "checkmark"`, 14px, `useThemeColors()`-resolved) — this is the one place a fraction is replaced rather than shown, because "4 of 4" is a redundant thing to read once true. **Not-yet-started/in-progress chip** (0 < completed < total, not current): `border-foreground-muted`, `bg-surface`, fraction shown as "N/M" in Label/muted.
- Tapping any chip jumps the pager to that exercise (does not require sets to be complete first — the strip is always fully navigable).
- **The strip is where "Add Exercise" (LOG-14) lives**, per D-12: a trailing `+` chip, same 48×48 floor, `border-foreground-muted`, dashed border (visually distinct "this isn't an exercise, it's an action" — same dashed-for-non-default-state language Phase 4's deload chip established), opens `ExercisePickerModal` in multi-select mode.

## Set Row (D-16/D-17/D-18) — the phase's highest-value contract

One row per set, rendered inside the current exercise's page. Not collapsible/expandable like Phase 4's slot row — every set row is always fully visible, since logging is the whole point of this screen.

**Layout, left to right:**
1. **Set number** (Body, regular, fixed 24px-wide column) — tapping it opens the set-type picker (Phase 7's surface; this phase renders the tap target but the picker only ever offers "Normal"/nothing changes, since `set_type` beyond `normal`/`warmup` is out of scope — see Phase-Wide Rules R7).
2. **Weight field** — the tappable value display plus its greyed reference, stacked: entered/prefilled value on top (Body, semibold once a real value exists, Body/regular placeholder-styled if still showing the unedited history-lookup prefill), the greyed previous-session value beneath in Label/muted with the accent-underline tap affordance (D-17) — or **"No previous"** in Label/muted with no underline (nothing to tap) on a first-ever set-number.
3. **Reps field** — identical stacked shape: prefilled target value on top, greyed previous actual beneath, tappable to autofill.
4. **RIR field** — identical stacked shape: prefilled target value on top, greyed previous actual beneath, tappable to autofill. (D-18: same keypad flow, third stop on the next-arrow walk.)
5. **Checkmark** — 48×48 `Pressable`, trailing edge. Unchecked: `border-foreground-muted` outline circle, no fill. Checked: `bg-accent` filled circle with a white checkmark glyph (D-19: tap again to undo, returns to the unchecked, editable state — never an "edit mode," the row's fields stay exactly where they are, just re-editable).

**Column proportions:** set-number column fixed at 24px; the three field columns share the remaining width equally (`flex: 1` each) at default content; because R4 (wrap-and-grow, inherited from Phase 4) forbids clipping, a field showing a wide value at large OS font scale grows its column and the row's overall height grows to accommodate — the row never clips, never scrolls horizontally, never shrinks a neighboring column below its content's minimum. The checkmark column is fixed at 48px regardless of font scale (glyph-only, not text-scaled — same rule as Phase 4's stepper buttons).

**Warm-up rows** render identically to working-set rows but with a leading **"W"** badge (14px circle, `bg-secondary`, `text-foreground-muted`, Label-role glyph) ahead of the set-number column, and are excluded from the exercise strip's completion fraction denominator per the Common Pitfalls guidance in RESEARCH.md (a warm-up completing does not move `3/4` to `4/5` — the fraction only ever counts working sets).

**One-off session rows (LOG-02/LOG-14, `EMPTY_PRESCRIPTION`):** the prefilled value shows **"—"** (em dash, same Phase 4 convention) instead of a target number wherever the target is null — reps and RIR both show `—` since a one-off exercise carries no program target; weight still resolves from history exactly as normal (D-16's weight source is independent of program-target presence).

## Numeric Keypad (D-20, RESEARCH §12)

Docks at the screen bottom on field focus (tapping any of the three field values in a `SetRow` activates it), a flex sibling of the scrollable set-row content, never `position: absolute`.

**Layout, top to bottom:**
1. **Reserved plate-strip band** — 40px, empty, always rendered (see Spacing exceptions above). Phase 6 fills this; this phase leaves it visually blank.
2. **Digit grid** — `1 2 3` / `4 5 6` / `7 8 9` / `. 0 ⌫` (decimal, zero, backspace), each key 56×56, `bg-surface` fill, Display-role glyph, `border-b border-foreground-muted/20` hairline separators (a new, phase-scoped 20%-opacity border treatment reserved for keypad-grid separators only — not a new semantic color, just an opacity modifier on the existing muted-foreground hex).
3. **Stepper row** beneath the grid — `[−]` / `[+]`, each 48×48 (the standard floor, not the 56px keypad-key exception — these are secondary controls flanking the primary digit grid), incrementing/decrementing by the field's natural unit (1 rep, 1 RIR notch, 2.5 or 0.5 depending on display unit for weight — reads from `packages/api-contracts`' existing increment convention, not a new one).
4. **Next/submit arrow** — trailing, full-height of the stepper row, `bg-accent` fill, white chevron glyph, 48×48 minimum. Walks weight → reps → RIR → complete per D-18; on the RIR field it reads **"Done"** (Label, white) instead of a bare arrow, and tapping it both submits the field and dismisses the keypad (there is no fourth field to advance to).

**The active field's value is never obscured** — this is LOG-05 read literally, structurally enforced by the reserved-band + flex-sibling layout: the scrollable set-row content sits above the keypad, and the actively-edited row scrolls into view above the reserved band the instant the keypad mounts (a scroll-into-view call on keypad-open, not a keypad-layout concern).

**No `TextInput` anywhere in this component** — the field itself is a `Pressable`/`View` displaying formatted text with a blinking-cursor affordance (a 2px `bg-accent` vertical bar, animated opacity, trailing the last digit) while active, never a real focusable native input, on any of the three platforms (RESEARCH §12's structural rejection of `TextInput`, `showSoftInputOnFocus`, and `readOnly` alike).

## Per-Exercise Action Bar (D-13)

A compact, always-visible row of three buttons beneath the current exercise's header on its pager page: **Warm-up**, **Targets**, **Note** — each a 48×48-minimum `Pressable` with a small Ionicons glyph above a Label-role text caption (`barbell-outline` / `options-outline` / `document-text-outline`, `useThemeColors()`-resolved), matching the visual weight of a bottom-tab-bar item, not a text button.

**Warm-up button always stays visible regardless of the `warmup_sets_enabled` global preference** (resolves RESEARCH.md Open Question 1) — the preference gates only whether tapping it pre-populates a suggestion at session start; the button itself is a stable member of the action-bar list constant D-13 requires, never conditionally hidden. Tapping it when no warm-up rows exist yet opens the **Warm-up sheet** (see Copywriting Contract); tapping it when warm-up rows already exist for this exercise opens the same sheet in an editing context (adjust working weight, regenerate).

**Note button** shows a filled-dot badge (6px, `bg-accent`, top-right corner of the button) when a note already exists for this exercise, empty/no-badge when it doesn't — the only badge treatment in this phase's action bar, since "does this exercise already have a note" is exactly the kind of state worth signaling before the user taps in.

**Targets button** opens the mid-workout targets sheet (D-14/D-15): session-only edit fields (identical stepper anatomy to Phase 4's `ExerciseSlotRow`, reused verbatim) plus, beneath them, a secondary **"Also update my program"** action (Body, `text-accent`, no fill — a lower-weight action than the sheet's own primary "Save" button, since write-back is the less common path per D-14's "session-only by default" framing).

**Overflow (`⋮`, trailing, 48×48, same button row):** opens `SessionActionSheet` with Swap, Remove, Reorder, Info — each row matching `RoutineActionSheet`'s existing shape from Phase 4 (icon + label, Remove rendered in Destructive color per the Confirmations table above, the rest in default foreground).

## Session Modes (D-32) — one screen, two/three states

A single typed `SessionScreenMode = 'live' | 'editing' | 'summary-correction'` value provided once at the screen root (React context), gating every timer-scheduling, auto-advance, and rest-state call site structurally — never inferred from `session.status`.

| Mode | Header Timer Bar | Auto-advance | Rest timer | Primary action | Trigger |
|---|---|---|---|---|---|
| `live` | Duration + rest, as specified above | Active (toggle-respecting) | Schedules on set completion | **"Finish Workout"** | LOG-01/LOG-02/D-33's `startSession` funnel, in-progress |
| `editing` | Replaced entirely by the session's date (Heading, centered, no numerals, no timer chrome) | Structurally unreachable — no auto-advance call site executes | Structurally unreachable — no scheduling call site executes | **"Done"** | History → edit a past workout (D-32), or D-33's add-a-past-workout entry point |
| `summary-correction` | Not rendered — the summary screen has its own layout (see Workout Summary) | N/A | N/A | **"Save Changes"** (inline, per corrected row) | Tapping "Edit" on any row of the finish summary before dismissing (LOG-19) |

**`editing` mode's visual tell:** the header region that would show "Workout"/"Rest" instead shows a single centered line — **"Editing {Weekday, Month D}"** (e.g. "Editing Tuesday, Aug 18") — Heading role, no accent, no numerals resembling a live timer, so the two modes are never visually confusable even at a glance.

## Home In-Progress Banner (D-28)

A full-width card on the Home tab, positioned above the existing Phase 4 "Next Up" card, rendered **only** when a session with `status IN ('in_progress', 'paused')` exists — never queried on the common no-session path per D-28's cost constraint (the query itself, not just the render, is conditional — see PLAN-level guidance).

**Layout:** `bg-secondary`, `md` padding, `border-l-4 border-accent` (a left accent bar — the one departure from a plain card border in this app's vocabulary, reserved for exactly this "something needs your attention" banner and not reused elsewhere). Heading line: **"Workout in Progress"** (Heading) with the live elapsed duration inline in muted Label ("47 min", recomputed on every Home-tab focus, not a running counter on this screen — Home is not the timer's home). Two actions beneath, side by side: **"Resume Workout"** (primary CTA fill, accent) and **"Discard"** (text-only, `text-destructive`, opens the Discard Workout confirmation from the Copywriting Contract before actually discarding).

**Paused variant:** heading reads **"Workout Paused"** instead of "Workout in Progress," same layout otherwise.

## Workout Summary (D-30/D-31, LOG-18/LOG-19)

A full-screen route reached automatically on tapping "Finish Workout." Not a modal over the workout screen — the live session's timers/rest state are torn down before this screen mounts (per D-32's structural-unreachability rule, `summary-correction` mode never coexists with `live` mode's scheduling).

**Layout, top to bottom:**
1. **Heading** — **"Workout Complete"** (Heading), with the session duration beneath in Body/muted.
2. **Muscles Trained** section — reuses `MuscleTargetList` (Phase 3/4 component) in a read-only, non-interactive rendering: chips for every muscle group with at least one working (non-warmup) set logged this session, no selection state, no tap affordance.
3. **Per-Exercise Breakdown** section — one row per exercise: name (Body, semibold), then a compact line of sets/reps/weight/volume, then **e1RM: {value}** or **e1RM: —** (D-31's validity cutoff, rendered exactly as specified in the Copywriting Contract). Any PR type detected for that exercise renders as one or more **"New PR"** badges (accent-filled, Label/semibold) trailing the exercise name — multiple PR types on one exercise show multiple badges side by side, wrapping to a second line rather than truncating (R4).
4. **Correction affordance (LOG-19):** each per-exercise breakdown row carries a trailing "Edit" text button (Body, `text-accent`, no fill) that expands that row in place into the exact same `SetRow` component the live screen uses, keypad included, in `summary-correction` mode — editing here writes through the same `logSet()`/PATCH path as the live screen (D-01's durability applies identically; there is no separate "save" step beyond the field's own submit).
5. **"Done"** primary CTA, full-width, pinned to the screen bottom, dismisses to Home.

**Empty per-exercise case:** an exercise added mid-workout but never logged (zero completed sets) does not appear in the breakdown at all — the breakdown lists only exercises with at least one completed set, matching the "muscles trained" section's own working-set-only inclusion rule.

## Phase-Wide Rules

Extends Phase 1's R1–R3 and Phase 4's R4–R6 (all still binding: wrap-and-grow, ~3s web cold-start bound, explicit-submit-may-block/passive-check-may-not, no truncation on new surfaces, structural validity over inline validation, no loading state for already-seeded local data). This phase adds:

- **R7 — Set-type tap target renders now, activates later.** The set-number tap target (Set Row, item 1) is built and rendered this phase per D-18's row anatomy, but its picker offers no choices beyond the current `normal`/`warmup` vocabulary (D-09/RESEARCH §2) — Phase 7 wires `drop`/`myorep`/`partial`/`failure`/`amrap` into the same already-rendered tap target. This phase must not render a disabled or hidden set-number control waiting for Phase 7; it renders the real, tappable surface with a currently-empty choice set.
- **R8 — The reserved plate-strip band never gains content this phase.** It is a layout placeholder only (Spacing exceptions above); no plate-math logic, hardcoded or otherwise, renders inside it in Phase 5. This is the explicit converse of R7: R7 pre-builds a tap target for Phase 7, R8 deliberately leaves a slot empty for Phase 6.
- **R9 — Every new timer-adjacent surface degrades to synchronous, in-app feedback when notifications are denied (D-23).** The header timer bar and rest full-screen view are functionally complete with zero OS notification permission granted — sound/haptic plus the persistent inline note (Copywriting Contract) are not a "lesser" experience path requiring separate design sign-off; they are this phase's baseline, with background OS alerting as the enhancement layered on top when permission is granted.
- **R10 — `live` mode's timer/auto-advance machinery is gated on the typed `SessionScreenMode` value only, never on `session.status` or a boolean prop** (D-32, Pitfall 3 from RESEARCH.md). This is a code-shape rule, not a pixel rule, but belongs in this contract because it is the structural guarantee that makes the Session Modes table above actually true at runtime rather than aspirational.

**Focal points** (Dimension 2 — mirrors Phase 1/4's precedent of naming a primary visual anchor per screen):
- **Active Workout screen (`live` mode):** the current exercise's set rows are the anchor — the header timer bar is deliberately secondary in visual weight (Display-sized numerals, but positioned above the fold, not center-stage) so the screen answers "what am I logging right now" before "how much time has passed."

- **Workout Summary:** the Muscles Trained chip row is the first thing seen after the heading, deliberately ahead of the numeric breakdown — the screen answers "what did I just accomplish" (a felt sense) before "what exactly were the numbers" (the per-exercise detail), matching how a user actually experiences finishing a workout.
- **Home In-Progress Banner:** the accent left-bar plus "Resume Workout" CTA is the single loudest thing on the Home screen whenever it's present — outranking even the Next Up card's own heading, since an abandoned in-progress session is explicitly the failure mode D-28 exists to prevent.
