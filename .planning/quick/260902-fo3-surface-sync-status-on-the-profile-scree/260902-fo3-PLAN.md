# Quick 260902-fo3 — Surface sync status on Profile, and forward the API URL into the Playwright web server

## Problem

Two independent blind spots, both exposed by the 260902-fei post-mortem.

**1. The sync status store has no consumer.** `apps/mobile/lib/sync-status.ts` records
`pendingWrites`, `lastPushOutcome`, `lastSuccessfulPushAt` and `rejectedOps`, and its own header
calls itself state "a future sync indicator renders". That future never arrived — `getSyncStatus`
is imported nowhere in the app. For eight days every boolean-bearing crud op was rejected
`invalid_field`, dropped from the queue by `isTerminalRejection`, and faithfully recorded in
`rejectedOps` where nobody could see it. The connector was already doing its job; the screen was
missing.

**2. `EXPO_PUBLIC_API_URL` never reaches the browser.** `playwright.config.ts`'s
`webServer.env` forwards exactly two keys (`EXPO_PUBLIC_DURABILITY_HARNESS`, `CI`). Playwright
passes that object as the child process environment, so a variable exported in the operator's shell
reaches `sync.spec.ts`'s Node-side `fetch` (which reads `process.env` in the test runner) but never
reaches `apps/mobile/lib/auth-storage.ts`'s `API_URL` inside the bundle Metro serves. The page and
the spec therefore talk to two different API hosts, and the spec fails in a way that looks like a
sync bug. Three audit runs were spent on this.

## Approach

Task 1 makes the existing store visible. `SyncStatusSection` is a pure presentational component
taking a `SyncStatus` prop, exported from `profile.tsx` exactly as `ToggleRow`/`GymRow` are, so
`profile.test.tsx` can invoke it as a plain function with no renderer. The screen adds one more read
to the `Promise.allSettled` pass it already runs on focus.

Time is formatted with a relative ladder (`Just now` / `5m ago` / `3h ago` / `2d ago`), not an
`Intl`/`toLocaleString` absolute — a locale- and timezone-free formatter is assertable in Jest
without pinning `TZ`, and "how stale is my sync" is a relative question anyway.

The section's state is seeded with an empty-but-valid `SyncStatus` rather than `null`, following the
`DEFAULT_PREFERENCES` precedent on this same screen. That removes the null branch from the component
entirely, so the four required test cases cover every branch it has.

Task 2 spreads the two variables into `webServer.env` only when they are set, so an unset variable
still falls through to the bundle's own `?? 'http://localhost:3000'` / `?? 'http://localhost:8081'`
defaults rather than being pinned to the string `"undefined"`.

## Constraints carried from the dispatch

- Do **not** run any Playwright project. The orchestrator has one running concurrently and will run
  again after this task lands. `pnpm --filter mobile typecheck` is the whole verification for Task 2.
- No new e2e spec, so `e2e/__durability.web.tsx` is not touched — this task has no shared-harness
  seam.
- Per `.claude/CLAUDE.md`: no comments restating what the code does, and no AI attribution anywhere
  including the commit message.

## Threat model

No new trust boundary: both changes read state the client already holds. No package installs, so
the package-legitimacy gate does not apply.

| Threat ID | Category | Component | Severity | Disposition | Mitigation |
|-----------|----------|-----------|----------|-------------|------------|
| T-FO3-01 | Information disclosure | rejected-ops warning line | low | mitigate | Render `table` and `reason` only — both closed server-defined vocabularies. Never render `opId` or any op payload, which carry user notes and bodyweight values. |
| T-FO3-02 | Information disclosure | `webServer.env` forwarding | low | accept | Only `EXPO_PUBLIC_*` variables are forwarded; the `EXPO_PUBLIC_` prefix is by definition bundle-inlined and public. No secret gains a new path into the bundle. |

## Tasks

### Task 1 — Render sync status on the Profile screen

**Files:** `apps/mobile/app/(tabs)/profile.tsx`, `apps/mobile/app/(tabs)/__tests__/profile.test.tsx`

**Formatter.** Export a pure `formatLastSync(isoTimestamp: string | null, now: number = Date.now()): string`
from `profile.tsx`, placed above the component:

| Input | Result |
|-------|--------|
| `null` | `Never` |
| < 60s ago | `Just now` |
| < 60min ago | `${minutes}m ago` |
| < 24h ago | `${hours}h ago` |
| otherwise | `${days}d ago` |

Floor each division. No `Intl`, no `toLocaleString`, no timezone — the injectable `now` is what makes
the ladder assertable without pinning `TZ` in Jest.

**Component.** Export `SyncStatusSection({ status }: { status: SyncStatus })` rendering the complete
section, header included, so the screen's JSX gains exactly one element:

- Section wrapper `<View className="gap-sm">` with a header
  `<Text className="text-label font-normal text-foreground-muted">Sync</Text>`, matching the
  `Workout settings` and `Gyms` sections.
- One card `<View className="gap-xs rounded-md border border-foreground-muted bg-surface px-md py-sm">`.
  No `minHeight: 48` — the card is non-interactive, so the touch-target rule the Pressable rows obey
  does not apply here, and no `accessibilityRole` is warranted for static text.
- Line 1, `text-body font-normal text-foreground`: `All changes synced` when `pendingWrites === 0`,
  `1 change waiting to sync` when it is 1, `${pendingWrites} changes waiting to sync` otherwise.
- Line 2, `text-label font-normal text-foreground-muted`:
  `Last synced ${formatLastSync(status.lastSuccessfulPushAt)}`.
- Line 3, rendered only when `status.rejectedOps.length > 0`, at `text-label font-normal text-destructive`
  — the muted type scale the screen already uses for secondary text, carrying the one alert colour
  the theme defines. Text: the rejected count with the same change/changes agreement as line 1, an
  em dash, then the **distinct** `${table}: ${reason}` pairs joined by `, `. Dedupe with a `Set` over
  the formatted pair, preserving first-seen order. Two ops rejected on the same table for the same
  reason produce one pair, not two.

A module-local (unexported) pluralisation helper for `change`/`changes` is fine; it is covered
through the component. Do not export it.

**Screen wiring.**

- `import { getSyncStatus, type SyncStatus } from '@/lib/sync-status';`. This is safe to import at
  module top level from a file the Jest suite loads: `sync-status.ts`'s only two imports are
  `import type` (erased at compile), and its `pending-write-count` dependency is a deferred
  `require()` inside `getSyncStatus` — so no new Jest mock is needed and none should be added.
- Add a module const beside `DEFAULT_PREFERENCES`:
  `const EMPTY_SYNC_STATUS: SyncStatus = { pendingWrites: 0, lastPushOutcome: null, lastSuccessfulPushAt: null, rejectedOps: [] };`
  and seed `const [syncStatus, setSyncStatus] = useState<SyncStatus>(EMPTY_SYNC_STATUS);`.
- Add `getSyncStatus()` as a sixth entry in the existing `Promise.allSettled` array inside
  `useFocusEffect`, destructure its result, and apply it with the same
  `if (result.status === 'fulfilled') set...` guard the other reads use. It must stay inside the
  `if (!userId) return;` guard.
- The comment above `useFocusEffect` states the pass makes *five* reads. That count is now wrong —
  correct that one word. Add no other comment to this file.
- Render `<SyncStatusSection status={syncStatus} />` as its own section between the closing `</View>`
  of the Gyms section and the Sign Out `<Pressable>`.

**Behavior (what the tests assert):**
- Zero pending renders `All changes synced`, and renders no rejection line.
- Three pending renders `3 changes waiting to sync`.
- A `null` `lastSuccessfulPushAt` renders `Never`.
- Two rejected ops sharing a table and reason render one `table: reason` pair and a count of 2.

**Tests.** Append to `apps/mobile/app/(tabs)/__tests__/profile.test.tsx`, importing
`SyncStatusSection` and `formatLastSync` alongside the existing named imports. Reuse the file's
`findText` walker and its direct-invocation convention — call the component as a function, never
render it. Build props from a small local `syncStatus(overrides: Partial<SyncStatus>): SyncStatus`
factory over `EMPTY_SYNC_STATUS`-shaped defaults.

Four `SyncStatusSection` cases, one per bullet above; the zero-pending case additionally asserts the
rejection sentence is absent, and the rejected case asserts the pair appears exactly once in the
joined text. Add one `it.each` over `formatLastSync` covering all five ladder rows with a fixed
`now`.

**Verify:**
```
pnpm --filter mobile test -- profile
pnpm --filter mobile typecheck
```
**Done:** `typecheck` exits 0; the profile-matching suites (7 files, including the four gym-profile
ones) are all green; the four new component cases fail if `SyncStatusSection` is reverted to a stub.

### Task 2 — Forward the API URL and web origin into the Playwright web server

**Files:** `apps/mobile/playwright.config.ts`

In `webServer.env`, keep `EXPO_PUBLIC_DURABILITY_HARNESS` and `CI` as they are and append two
conditional spreads, each contributing its key only when `process.env` has a non-empty value for it:
`EXPO_PUBLIC_API_URL`, then `EXPO_PUBLIC_WEB_APP_ORIGIN`. Spreading `{}` when unset is what keeps
`auth-storage.ts`'s `?? 'http://localhost:3000'` and `web-app-origin.ts`'s
`?? 'http://localhost:8081'` in force — assigning `process.env.X` unconditionally would hand the
child the string `"undefined"`, which `web-app-origin.ts` throws on at import.

Do not restructure the surrounding `webServer` block, and do not touch either project definition.

One comment is permitted here and nothing more: `reuseExistingServer: !process.env.CI` means an
already-running dev server is reused with whatever environment it was originally started with, so a
newly exported variable silently does not apply until that server is restarted. That is a genuine
trap — it is the reason this went unnoticed — and a reader cannot infer it from the config. Write it
as one short line above `env`, or fold it into the existing block if it reads better there. Add no
comment restating what the spread does.

**Verify:**
```
pnpm --filter mobile typecheck
```
Do **not** invoke `playwright test`, `pnpm --filter mobile test:e2e`, or `test:e2e:durability` — the
orchestrator is running a project concurrently and a second run would contend for port 8081 and the
single-worker durability server.

**Done:** `typecheck` exits 0; `webServer.env` yields exactly two keys when neither variable is set
and four when both are.
