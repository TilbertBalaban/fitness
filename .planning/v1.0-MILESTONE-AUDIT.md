### The 5 `sync` failures

All five cases in `e2e/sync.spec.ts` — the entire `sync` project — failed with
`TypeError: fetch failed`. They are not a regression:

- The failure is uniform across 100% of the project, not scattered assertions.
- The `sync` project is documented in `playwright.config.ts` as needing the live service
  stack, and deliberately fails loudly rather than skipping when it cannot reach it.
- Root cause is a **port mismatch, not a missing service**. `sync.spec.ts` defaults
  `API_BASE_URL` to `http://localhost:3000`, but this environment's API listens on
  **:4000** (`main.ts` uses `process.env.PORT ?? 3000`, and `PORT=4000` is set here). The
  API was up the whole time — a second start attempt failed with `EADDRINUSE :::4000`,
  which is what proved it. Running the project without `EXPO_PUBLIC_API_URL` therefore
  points every case at a dead port.
- Postgres, the PowerSync Service, and Mailpit were all running throughout;
  `POWERSYNC_URL` answered `200` on `/probes/liveness`.
- The first thing the spec does is `fetch(${API_BASE_URL}/v1/auth/sign-up/email)`.

The 116 `durability` cases that passed run against a real browser and a real
`@powersync/web` database with no API dependency, so the offline-write half of the
local-first guarantee is genuinely proven; the server round-trip half is re-run below.
